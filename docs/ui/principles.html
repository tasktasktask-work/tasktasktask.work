UI Principles

UI設計方針

既存の課題管理ツールの画面をそのまま真似ない、と決めた。 ただし用語は、開発者以外にも通じるものであれば流用する。 その線引きの上で、画面をどう作るかをここに定める。

この製品が扱う情報の性質

三つの種別が同じ一覧に並ぶ。 階層に深さの制限がない。 状態は進捗率という数値ひとつしかない。

この三つが、画面設計の制約をほぼ決めている。 種別が混在するので、どの行が何なのかを一目で見分けられなければならない。 階層が深くなりうるので、入れ子表示だけに頼ると読めなくなる。 状態が数値なので、意味づけは表示の側が引き受ける必要がある。

基本方針

色だけで意味を伝えない

種別、進捗、タグ。 どれも色で区別できるが、色は必ず文字か形と組み合わせる。

種別バッジは色と形の二重符号ThreadTypeBadge
課題朱 / 四角
議論藍 / 丸
質問緑 / 菱形

バッジの左にある小さな印は、種別ごとに形が違う。 色覚の違いで朱と緑の判別がつかない場合でも、四角と菱形で見分けられる。 文字も併記しているので、印が見えなくても読める。

階層は場所によって見せ方を変える

スレッド一覧は平らに並べ、親子はリンクで辿る。 ガントチャートは入れ子で並べ、折りたためる。

同じデータを二つの画面で違う形に見せることになるが、これは目的が違うからである。 一覧は探すための画面で、担当者やタグで絞るとき階層は邪魔になる。 ガントは計画の構造を読むための画面で、親と子の期間の関係は入れ子でなければ読み取れない。

数値の意味づけは表示が引き受ける

データベースに入っているのは0から100の整数だけである。 それを課題では「進捗率」として数値のまま出し、 議論と質問では「オープン」「クローズ」という言葉に置き換える。

質問の画面に「進捗率100%」と出ても、読み手には何のことかわからない。 同じ列を使っていることは、画面の側では見せない。

できないことは、できないと見せる

アーカイブされたスレッドでは、コメント欄も子スレッド追加のボタンも消す。 無効化して灰色で残すのではなく、消す。

ガントのバーはドラッグできないので、掴めそうな見た目にしない。 カーソルも変えない。

意匠

色

役割値使いどころ
朱#c8402c課題、担当者のハンコ、選択中、進捗のバー
藍#2c4a75議論、リンク、親バー
緑#3f6b52質問、完了
黄#8f6410はみ出し警告、期間未設定、期限が近い
墨#171b22本文
生成り#f6f3ec地

朱を主役に置く。 ハンコアバターの色でもあり、この製品の印象を決める色である。 藍と緑と黄は、朱に対する副色として抑えた彩度で使う。

書体

用途書体理由
見出ししっぽり明朝 B1日本語の見出しに重心がある。ゴシックだけの画面より読む位置が定まる
本文Zen角ゴシック New画面上の可読性が高く、字面が均一
識別子と数値JetBrains MonoWEB-128 や日付を等幅で揃える

識別子、日付、進捗率の数値は必ず等幅で組む。 一覧で縦に並んだときに桁が揃い、比較できるようになる。

余白と罫

影を使わず、1pxの罫で境界を引く。 背景には薄い方眼を敷く。 設計図の紙面という見立てを、全体で保つ。

画面をまたぐ約束

要素約束
識別子常に WEB-128 の形で出す。番号だけで表示しない
人必ずハンコアバターと表示名を並べる。メールアドレスは出さない
日付9/8 – 9/19 の形。年は今年でなければ添える
日時2026-09-04 13:02 の形。組織のタイムゾーンで表示する
アーカイブ済み斜線の地紋を敷き、文字を薄くする
組織の切り替えURL に /o/{slug}/ を必ず含める。画面上部にも組織名を出す
未認証/login へ送らず、そのURLのままログイン画面を出す。認証後は同じURLに着地する

操作の重さに応じた確認

操作確認理由
進捗率の変更なしいつでも戻せる
アーカイブあり一覧から消えるため。連鎖しないことも伝える
非公開から公開へあり戻せても、見られた事実は戻せない
論理削除あり復元できるが、組織管理者しか気づけない
コメントの投稿なしただし編集も削除もできないことを投稿欄に明示する

最後の行が重要である。 投稿ボタンを押した後で取り返せないのに、押す前に何も伝えないのは不親切にあたる。

新しい画面を作るとき

  1. 近い既存ページを複製して雛形にする
  2. 種別、進捗、人、日付は既存のコンポーネントを使う。新しく作らない
  3. 色を足したくなったら、まずこの表の四色で表せないかを考える
  4. できない操作は消す。無効化して残さない
  5. ページモックに追加し、サイドバーにも登録する
