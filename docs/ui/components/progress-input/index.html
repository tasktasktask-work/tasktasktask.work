進捗率入力

1刻みで自由に入れられる。 ただし実際に選ばれる値はほとんど 0、25、50、75、100 に偏る。 その両方を一つの入力欄で満たす。

datalist を使う

選択式にすると細かい値が入れられない。 自由入力だけにすると、よく使う値を毎回打つことになる。 <input type="range"> に <datalist> を添えると、両方が成り立つ。

<input type="range" min="0" max="100" step="1"
       list="progress-marks" value="40">
<datalist id="progress-marks">
  <option value="0"></option>
  <option value="25"></option>
  <option value="50"></option>
  <option value="75"></option>
  <option value="100"></option>
</datalist>

<input type="number" min="0" max="100" step="1" value="40">

スライダーには目盛りが表示され、その位置に吸い付く。 隣に数値の入力欄を置き、キーボードでも直接打てるようにする。

入力欄ProgressInput（課題）
%

議論と質問では形が変わる

0か100しか取らないので、スライダーは使わない。 オープンとクローズの二択として出す。

入力欄OpenCloseToggle（議論と質問）

保存される値は課題と同じ progress 列だが、 画面には数値を出さない。 質問の詳細に「進捗率100%」と表示されても、読み手には何のことかわからない。

表示側

表示ProgressMeter
0%0 / 灰
25%1–99 / 朱
60%1–99 / 朱
100%100 / 緑

0のときバーを灰にするのは、朱の1%が見えないためである。 100を緑にするのは、完了だけは一目で区別したいからである。 数値は等幅で組み、一覧で縦に並んだときに桁が揃うようにする。

誰が入力するか

担当者の自己申告である。 親の進捗率も子から計算せず、人が入れる。

この入力欄で表せないこと

「やらないと決めた」と「まだ手をつけていない」は、どちらも0のままになる。 「レビュー中」のような工程も数値では表せない。

どう扱うかは各組織の運用に委ねる方針を取った。 経緯は却下の表現に記録している。
