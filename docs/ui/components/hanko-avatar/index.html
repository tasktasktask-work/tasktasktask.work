ハンコアバター

表示名の一文字目を朱色の枠に収める。 画像のアップロードは受け付けない。

なぜ画像を受け付けないか

アップロードを許すと、トリミングのUI、複数解像度の生成、差し替えの導線が必要になる。 添付ファイルとは別の画像処理を作ることになる。

一方、この製品で人が現れる場所は、担当者、コメントの書き手、メンションの候補の三つに限られる。 どれも「誰か」が識別できれば足りる。 表示名から生成すれば、同じ人はどの画面でも同じ見た目になり、実装も一つで済む。

生成の規則

function hanko(displayName: string) {
  const trimmed = displayName.trim();
  // 書記素単位で先頭一文字を取る（絵文字や結合文字を割らない）
  const first = [...new Intl.Segmenter('ja', { granularity: 'grapheme' })
                  .segment(trimmed)][0]?.segment ?? '?';

  const initial = /^[a-z]$/i.test(first) ? first.toUpperCase() : first;
  const hash    = fnv1a(trimmed);          // 表示名全体から取る

  return {
    initial,
    color: PALETTE[hash % PALETTE.length],  // 朱、藍、緑、黄土、墨
    shape: (hash >> 8) % 2 === 0 ? 'circle' : 'square',
  };
}

ハッシュは表示名全体から取る。 一文字目だけから取ると、姓が同じ人が全員同じ色と形になる。

書記素単位で切り出すのは、絵文字や結合文字を含む表示名で文字が割れないようにするためである。 displayName[0] ではサロゲートペアの片割れを取ってしまう。

同じ見た目の人が出る

色5種と形2種で10通りしかないので、同じ姓の人が多い組織では見た目が重なる。 アバターは補助であり、識別は表示名で行うという前提を崩さない。 一覧の行では常にアバターと表示名を並べる。

読み上げへの配慮

アバターは装飾なので aria-hidden="true" を付ける。 隣に表示名があるため、読み上げで「佐 佐藤明日香」と二重になるのを避ける。
