slug は変えられません。URL に入っていて、外に貼られたリンクがそれを指しているためです。 言語とタイムゾーンは、選べる値が増えたときに変えられるようにします。

メンバーには、この画面が無い

サイドバーに「設定」が出ない。 URL を直接開いた場合は 404 を返す。

権限が無いことを、権限が無いと伝えない

「あなたには権限がありません」と出しても、できることは変わらない。 伝わるのは「そこに何かがある」という事実だけである。

所属していない組織の URL も、同じく 404 を返す。 区別すると、slug を総当たりして他社の存在を確かめられる。

slug を変えられなくした理由

slug は URL に入っている。 変えると、貼られたリンクと開いているタブが行き先を失う。

プロジェクトキーを変えられなくしたのと同じ判断である。 どちらも識別子として外へ出ていくので、後から入れ替えると読み手の側が壊れる。

表示に使う名前は変えられる。 会社名が変わっても、URL はそのままでよい。

添付の数字が、上限ではない理由

組織あたりの総量に上限を置いていない。 課金の形が決まっていない段階で数字を決めると、その数字がそのまま仕様になる。

いま要るのは上限より、埋まりかけたことに気づく手段である。 サーバー側のディスク監視は「もう危ない」ことしか教えず、 どの組織が食っているかは、そのとき調べ直すことになる。 ここに二つの数字が出ていれば、探す前に見当がつく。

数えるのは組織のすべての添付ファイルで、 自分に見えない非公開プロジェクトのぶんも含む。 ディスクを実際に食っている量を伝えるための数字なので、見える範囲に絞る意味がない。 詳しくは添付の合計にある。
