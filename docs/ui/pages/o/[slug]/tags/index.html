どのスレッドにも付いていません。もう一度押すと消えます

消すと、付いていたスレッドとの結びも一緒に消えます。取り消せません。 件数はこの組織のすべてのスレッドを数えたもので、 自分に見えないプロジェクトのぶんも含みます。

消す押しボタンが二度押しである理由

四行目が一度押したあとの状態である。 文言が「消す」から「本当に消す」に変わり、何件から外れるかが横に出る。 この時点ではまだ何も起きていない。

確認の窓を出す案もあった。やめたのは、 窓は押し慣れると読まれなくなるからである。 出るのがいつも同じ形なら、文面が変わっても目は止まらない。 押しボタン自身の文言が変われば、押した手のほうが「変わった」ことに気づく。

それでも取り違えは起こりうる。backend の128件は、 押した瞬間に戻せなくなる。だから 使用数を数字で出している。

使用数が見えない範囲まで数える理由

数えるのは組織のすべてのスレッドで、自分に見えない 非公開プロジェクトのぶんも含む。

見える範囲に絞るほうが、他の画面との揃いはよい。それでも全体を数えているのは、 この数字が「消したら何件から外れるか」の歯止めだからである。 絞ると、実際より少ない数を見せることになる。 「3件」と読んで押した先で、見えていなかった20件も一緒に外れる。

引き換えに、非公開プロジェクトでそのタグがどれだけ使われているかが数として見える。 出るのは件数だけで、何のスレッドかは分からない。

名前の欄が入力欄のまま置いてある理由

タグは名前と色しか持たない。 そのために編集画面へ移らせると、往復のほうが操作より長くなる。

打ち間違えたタグを直せることには、それ自体の意味がある。 四行目の bakcend は、まだ誰にも使われていないので消してよい。 ところが128件に付いてから気づいた場合、消して作り直す道しかないと、 結びが消えたぶんを人が思い出して付け直すことになる。
