タグの欄に入り口が三つある理由

付いている札それぞれの×、名前を打って足す欄、そして畳んだチェックの一覧。 同じ操作に三つの道があるのは、多いように見える。

打つ側を主にしてあるのは、タグが 組織の単位で誰でも作れるためである。数十個まで増えうる。 その数のチェックボックスを常に開いておくと、属性欄が縦に伸びて、 進捗率も期間も画面の外へ出る。 畳んでおけば、他の欄の位置が動かない。

札の×を残したのは、一つ外すためだけに一覧を開かせないためである。 チェックの一覧は付いているものと付いていないものを同時に扱うので、 「これを外す」という一手には重い。

名前の欄は datalist で補助する。ただし補助であって制限ではないので、 一覧に無い名前も送れてしまう。作れるのは 管理画面だけなので、 届いた側で断り、そこへのリンクを添える。

ウォッチの欄に人数を出さない理由

押しボタンが一つあるだけである。自分が付けているかどうかしか出ない。

誰がウォッチしているかを並べる案もあった。やめたのは、 人数だけでも、少人数の組織では誰が見張っているかが割れるからである。 ウォッチは自分あての設定であって、 他の人に見せる情報ではない。

アーカイブされたスレッドでも、この押しボタンだけは残る。 畳んだ先に新しいコメントは付かないので通知は飛ばないが、 外す手立てまで消えると、開け直したときに困る。

投稿欄に警告を出す理由

コメントは投稿すると編集も削除もできない。 押した後で取り返せないのに、押す前に何も伝えないのは不親切にあたる。

そこで投稿ボタンの並びに一文を置く。 確認ダイアログにはしない。毎回出れば読まれなくなり、投稿そのものが億劫になる。

本文とコメントの扱いの違い

タイトルの下に「本文編集済み」の印がある。 本文は編集できるが、コメントはできない。

印が指すのは本文だけである。タイトルを直しても付かない。 誤字を一文字直しただけで印が付くと、それを見た人は、 並んでいるコメントが古い本文に向けられていないかを毎回疑うことになる。

本文は「現在の課題の定義」であり、調査が進めば書き換わってよい。 コメントは「その時点の発言」なので不変にする。

ただし本文が黙って書き換わると、それを前提に書かれたコメントが宙に浮く。 上の例では、田中のコメントが「ページングはカーソルで」と言い、 そのあと佐藤が本文に反映している。 編集済みの印は、この順序を追うための手がかりになる。

書き換える欄は、対象の隣にある

タイトルは見出しの隣、本文は本文の直下に「編集」がある。 押すと、その位置の読み表示が入力欄に入れ替わる。読み表示は消える。 どちらが今の値なのかを、迷わせないためである。

以前は画面の下端に「タイトルと本文を書き換える」という欄が一つあり、 コメントの列を越えた先で畳んであった。 畳んであること自体は正しい。この画面の主役は読むことで、書き換えは時々である。 遠かったのは入口ではなく、入口と対象の距離のほうだった。

入口は summary で、リンクではない。 書き換える動線を、リンクにしないの規約は、 Link が画面に現れた時点で行き先を先読みすることへの備えである。 ここは開閉するだけでサーバー側が動かない。

保存できたら閉じて読みへ戻り、「保存しました」が読み表示の上に出る。 失敗したときは開いたままにする。直す対象が画面にないと直せない。 保存の隣に「やめる」を置いたのは、読み表示が消えている状態で、 元へ戻る道が画面にないと手が止まるためである。

子スレッドと添付を右へ置いた理由

どちらも本文の列を占めていた。 子スレッドは辿る先であって、この画面で読むものではない。 添付を足す欄は操作であって、内容ではない。

添付の一覧のほうは本文の列に残してある。 仕様書や画面の写しは本文の側の情報で、18remの欄に畳むと、 中身を確かめるために結局押すことになる。

右の欄では、高さの変わらないものを上に積む。 添付を足す欄、属性、親スレッド、子スレッドの順である。 子スレッドは0件から十数件まで伸びるので、上に置くと、 その下の落とす欄の位置がスレッドごとに変わる。 添付の欄は高さが固定なので、一番上に置いても下の欄は動かない。 押す回数が多いものから順に並ぶ。

親は属性の表から出して、子スレッドの真上に置いてある。 表の中の1行だと、進捗率や担当者と同じ重みにしか見えず、付け替えられること自体が伝わらない。 出したうえで、いまの親を子と同じ形の行で見せる。 番号だけが入った入力欄では、どのスレッドが親なのかを読めない。

子スレッドの行は一覧の行を狭めたものではない。 一覧は横に並べて比べるための形で、こちらは一件ずつ辿るための形である。 下の段に「親からはみ出し」の印を出す。 上に出る警告と対になっていて、どの子がはみ出しているのかは、ここでしか分からない。

0件のときは欄ごと出さない。子を立てる導線だけが残る。

添付は選んだ時点で送られる

右の欄に落とすか、ファイルを選ぶと、そのまま送信まで終わる。押しボタンは無い。

以前は「選ぶ」と「添付する」の二段だった。 二段目は押し忘れたときにだけ意味を持つ押しボタンで、 ところが押し忘れたことは画面から分からないので、意味を持つ場面が来ない。 間違えて付けたものは、一覧の側から一押しで消せる。

受け皿はその欄の中だけである。 本文の列まで広げると、本文の文字を選んで動かしたときに紛れる。

断るときは選んだものを欄から捨てる。押しボタンが無いので、直してもう一度押す機会がない。 「添付する」は noscript の中に残してあり、 JavaScript が動かない環境ではそちらが受ける。

コメントの投稿欄は二段のままである。 こちらは本文と添付を一つの送信で出すので、選んだ時点では送れない。

関連するスレッドを作る導線

右の欄の子スレッドの下に「このスレッドを親にして 課題 / 議論 / 質問 を作成する」を置いてある。 三つの語はそれぞれ種別のラジオで、押すと下にタイトル欄が出る。 押した語が種別になるので、開いた先で選び直すことはない。 立てると、すぐ上の子スレッドの一覧に行が増える。

立てたあとも、押した語は選ばれたまま残る。 子の課題を続けて並べるときに、毎回押し直すことにならない。

本文のすぐ下に置いてあったものを、子スレッドの欄と一緒に移した。 親子を扱う場所が二つに分かれているより、一つにまとまっているほうが探しやすい。

種別は後から変えられない。 議論として立てたものを課題に作り変えることはできないので、 議論を読んでいる最中に課題を立てるのがいちばん自然な流れになる。 そのとき番号を書き写させると、書き写さない人が出て、親子が切れる。

誰がこの画面で書き換えられるか

このプロジェクトを閲覧できる人なら誰でも書き換えられる。 進捗率も担当者も期間も親も、そしてアーカイブも同じである。

削除だけが違う。 組織管理者以外には、削除の欄そのものが出ない。 押せない押しボタンを見せて断るより、出さないほうがいい。

畳んでいないスレッドでも出ない。削除できるのはアーカイブを経たものだけなので、 組織管理者から見ても、条件が揃うまで欄は現れない。 上の見本に削除の欄が無いのは、このスレッドが畳まれていないためである。

条件にプロジェクト側のアーカイブは入らない。 畳んだプロジェクトの中では、畳むことも戻すこともできないが、 畳んだスレッドを消すことはできる。

右の欄

属性、添付を足す欄、子スレッドの三つが縦に積んである。 罫は箱ごとに持たせ、見出しは属性欄の項目名と同じ字面にしてある。 本文の列の見出し（明朝の太字に下罫）と同じ形にすると、右が本文の続きに見える。

この画面でだけ、進捗率と期間と担当者を変更できる。 ガントのバーはドラッグできないので、期間を変えるならここへ来る。

ウォッチしている人を出しているのは、 自動では付かない仕様のため「誰が見ているか」が自明でないからである。 ここに自分がいなければ、コメントが付いても通知は来ない。

チェックボックス

本文にもコメントにも - [ ] やること と書ける。 押せるのは、そのプロジェクトを閲覧できる人なら誰でもである。

本文の箱を押すと、本文そのものが書き換わる。 それでも「編集済み」の印は付かない。 項目はもとから並んでいて、終わったかどうかだけが動くからである。

コメントの箱を押しても、コメントの本文は一字も変わらない。 状態は別のテーブルにあり、 誰がいつ入れたかもそちらに残る。

この見本にはまだ動かない部分がある

コメントを消す動線は出していない。 組織管理者だけが消せると決めてあるが、 押す前に何を確かめさせるかを決めていない。

添付の並べ方

再エンコードできた画像は、 そのまま並べる。名前の行だけにすると、中身を確かめるための往復が読む人の数だけ起きる。 押すと新しいタブで開く。拡大も保存も、ブラウザのものがそのまま使える。

読めなかったファイルは、名前と大きさの行だけになる。 画像の下にも同じ行が付く。名前と大きさはどのみち出す必要があり、 消す押しボタンの置き場も要るためである。 画像の上に重ねると、画像そのものを押したいときと当たる。

並ぶのは付けた順である。 新しいものを上にすると、本文やコメントの中で「上の画像が」と書かれたときに、 その指し先が後から動く。

消す押しボタンが出るのは、上げた本人と 組織管理者にだけである。 一度押すと「本当に消す」に変わる。実体ごと消えて取り消せない。

アーカイブされている場合

投稿欄と、子スレッドを追加する導線を消す。 タイトルと本文の「編集」も、添付を落とす欄も出ない。 無効化して灰色で残すのではなく、消す。 読めるが書けない状態であることを、画面の構造で示す。

入れ替わりに、削除の欄が出る。組織管理者にだけである。 右の欄に残るのは、読み取りの属性と、子スレッドの並びと、ウォッチの押しボタンだけになる。 ウォッチは自分あての設定なので、畳んだスレッドでも付け外しできる。
