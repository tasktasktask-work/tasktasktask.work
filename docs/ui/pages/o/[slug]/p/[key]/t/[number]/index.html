投稿欄に警告を出す理由

コメントは投稿すると編集も削除もできない。 押した後で取り返せないのに、押す前に何も伝えないのは不親切にあたる。

そこで投稿ボタンの並びに一文を置く。 確認ダイアログにはしない。毎回出れば読まれなくなり、投稿そのものが億劫になる。

本文とコメントの扱いの違い

タイトルの下に「編集済み」の印がある。 本文は編集できるが、コメントはできない。

本文は「現在の課題の定義」であり、調査が進めば書き換わってよい。 コメントは「その時点の発言」なので不変にする。

ただし本文が黙って書き換わると、それを前提に書かれたコメントが宙に浮く。 上の例では、田中のコメントが「ページングはカーソルで」と言い、 そのあと佐藤が本文に反映している。 編集済みの印は、この順序を追うための手がかりになる。

関連するスレッドを作る導線

本文のすぐ下に「関連する課題を作成する」を置いてある。 ここから立てると、このスレッドが親に入った状態で 立てる画面が開く。

種別は後から変えられない。 議論として立てたものを課題に作り変えることはできないので、 議論を読んでいる最中に課題を立てるのがいちばん自然な流れになる。 そのとき番号を書き写させると、書き写さない人が出て、親子が切れる。

誰がこの画面で書き換えられるか

このプロジェクトを閲覧できる人なら誰でも書き換えられる。 進捗率も担当者も期間も親も、そしてアーカイブも同じである。

削除だけが違う。 組織管理者以外には、削除の欄そのものが出ない。 押せない押しボタンを見せて断るより、出さないほうがいい。

右の属性欄

この画面でだけ、進捗率と期間と担当者を変更できる。 ガントのバーはドラッグできないので、期間を変えるならここへ来る。

ウォッチしている人を出しているのは、 自動では付かない仕様のため「誰が見ているか」が自明でないからである。 ここに自分がいなければ、コメントが付いても通知は来ない。

チェックボックス

本文にもコメントにも - [ ] やること と書ける。 押せるのは、そのプロジェクトを閲覧できる人なら誰でもである。

本文の箱を押すと、本文そのものが書き換わる。 それでも「編集済み」の印は付かない。 項目はもとから並んでいて、終わったかどうかだけが動くからである。

コメントの箱を押しても、コメントの本文は一字も変わらない。 状態は別のテーブルにあり、 誰がいつ入れたかもそちらに残る。

この見本にはまだ動かない部分がある

タグ、ウォッチ、添付は、それぞれ別の機能として作っていない。 実際の画面には、いまその欄が出ない。 上に描いてある 📎 のリンクと「ファイルを添付」の押しボタンも出ない。

コメントを消す動線も出していない。 組織管理者だけが消せると決めてあるが、 押す前に何を確かめさせるかを決めていない。

アーカイブされている場合

投稿欄と、子スレッドを追加するボタンを消す。 無効化して灰色で残すのではなく、消す。 読めるが書けない状態であることを、画面の構造で示す。
