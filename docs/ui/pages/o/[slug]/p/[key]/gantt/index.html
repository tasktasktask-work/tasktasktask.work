この図から読み取れること

一行目の親に警告が出ている。 子である「検索UIの実装」が、親のバーの右端を越えているためである。 はみ出した子のバーは黄色になる。

システムは日付を書き換えない。 親の締切を延ばすのか、子を前倒しするのかは人が決める。 親子関係に集計の意味を持たせていないので、 警告は事実を伝えるだけである。

「旧検索ロジックの撤去」は薄い。 進捗率が100だからである。消さずに残すのは、 そこに何があったかを時間軸の上で見せるためである。

縦の朱線は今日を示す。 この線より左にあるのに塗りが進んでいないバーは、遅れているという意味になる。

図の下の別枠

期間が入っていない課題は時間軸に置けない。 だからといって表示から外すと、ガントに載っていない課題があること自体に気づけなくなる。

この枠が空になっていれば、プロジェクトの全課題が計画に載っているという意味になる。 逆に件数が増えていくなら、計画されないまま溜まっている作業があるということである。

階層で並べる理由

スレッド一覧は平らに並べるのに、こちらは入れ子にする。 一覧は探すための画面で、絞り込むときに階層は邪魔になる。 ガントは計画の構造を読むための画面で、親と子の期間の関係は入れ子でなければ読み取れない。

議論と質問はここに現れない。 期間を持たないので時間軸に置けず、行としても出さない。
