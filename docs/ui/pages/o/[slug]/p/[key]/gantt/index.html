この図から読み取れること

一行目の親に警告が出ている。 子である「検索UIの実装」が、親のバーの右端を越えているためである。 はみ出した子のバーは黄色になる。

システムは日付を書き換えない。 親の締切を延ばすのか、子を前倒しするのかは人が決める。 親子関係に集計の意味を持たせていないので、 警告は事実を伝えるだけである。

「旧検索ロジックの撤去」は薄い。 進捗率が100だからである。消さずに残すのは、 そこに何があったかを時間軸の上で見せるためである。

「旧基盤の縮小計画」は枠線だけになっている。 アーカイブ済みだからである。 畳んであっても、下に生きた子がぶら下がっているので親としては残る。 薄さは進捗率100に、中抜きは畳んだものに割り当ててあり、二つを見分けられる。

縦の朱線は今日を示す。 この線より左にあるのに塗りが進んでいないバーは、遅れているという意味になる。

バーの無い行と、下の別枠

「移行の段取り」にはバーが無い。期間が入っていないためである。 それでも図に残っているのは、期間を持つ子がぶら下がっているからで、 親を落とすと子のインデントの根拠が消える。

同じ課題は下の別枠にも出ている。二重に見えるが、言っていることは違う。 図の行は「子がここにぶら下がっている」ことを示し、別枠の行は「まだ計画に載っていない」ことを数え上げている。

この枠が空になっていれば、動いている課題はすべて計画に載っているという意味になる。 逆に件数が増えていくなら、計画されないまま溜まっている作業があるということである。

親から外れて見える行

いちばん下の「キャッシュ方式の切り替え」には、名前の横に ↳WEB-31 と出ている。 この課題の親は議論で、議論は時間軸に置けないので行として出せない。 行の無い親の下にインデントしても、なぜ下がっているのかが読めないため、最上位に上げてある。 上げただけでは理由が伝わらないので、親の番号を添えている。

上の欄にあるもの

絞り込みは置いていない。担当者で絞ると、条件に合わない親が消えて子だけが残り、 その置き場所をもう一度決めることになる。探すのはスレッド一覧の役目である。

代わりに置いてあるのは、件数と描いている範囲、 そして今日へ戻るための一つだけである。 分母は畳まれていない課題で、終わったものも含む。

階層で並べる理由

スレッド一覧は平らに並べるのに、こちらは入れ子にする。 一覧は探すための画面で、絞り込むときに階層は邪魔になる。 ガントは計画の構造を読むための画面で、親と子の期間の関係は入れ子でなければ読み取れない。

三角を押すと子孫の行が隠れる。 折りたたみであって、畳む（アーカイブ）ではない。 閉じても親のバーは変わらず、隠れた件数と、その中のはみ出しの有無は親の行に残る。

議論と質問はここに現れない。 期間を持たないので時間軸に置けず、行としても出さない。
