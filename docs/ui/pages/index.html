URL の構造

/                                       所属している組織の一覧
/login                                  ログイン
/signup                                 組織を作る（未ログインならアドレスの確認から）
/join?token=...                         招待の受諾
/me                                     アカウント（組織に依らない）
/o/{slug}                               プロジェクト一覧
/o/{slug}/members                       メンバーと招待
/o/{slug}/settings                      組織の設定（組織管理者だけ）
/o/{slug}/dashboard                     担当スレッドと通知
/o/{slug}/billing                       支払いと請求（組織管理者だけ）
/o/{slug}/p/{key}                       スレッド一覧
/o/{slug}/p/{key}/gantt                 ガントチャート
/o/{slug}/p/{key}/t/{number}            スレッド詳細

組織を示す {slug} を必ず含める。 ひとりが複数の組織に所属するため、URLを見てどの組織かがわからないと取り違えが起きる。

ログインより手前の画面（/login、/signup、/join）に {slug} は無い。 どの組織を見るかが、まだ決まっていないためである。 /signup にいたっては、これから作る組織の slug をその画面で決める。

ログインしたあとで例外なのは /me だけである。 ここで触る値は組織の外側にあり、所属しているすべての組織に効く。 {slug} を含めると、その組織だけの設定に見える。

スレッドのURLに使うのは {number} だけで、プロジェクトキーは重複しない。 番号は組織の中で通し番号なので、/o/acme/p/WEB/t/128 の WEB と 128 は どちらもプロジェクトを特定しうるが、キーのほうを人間向けの手がかりとして残している。

共通のレイアウト

組織の中の画面は、上帯と左帯を共有する。 ログイン、招待、組織の一覧、そして /me には左帯が付かない。 どれも組織に属していない人が開きうる画面で、そのとき左帯に並べるものが一つも無い。

┌────────────────────────────────────────────────┐
│ [3] TASK3    株式会社アクメ acme    🔔3  [佐]  │ 上帯
├──────────────┬─────────────────────────────────┤
│ プロジェクト  │                                 │
│  WEB 検索基盤 │   ページごとの内容               │
│  BILL 請求   │                                 │
│              │                                 │
│ わたし        │                                 │
│  担当スレッド │                                 │
│  通知        │                                 │
│  アカウント   │                                 │
└──────────────┴─────────────────────────────────┘

「アカウント」だけは行き先が組織の外（/me）である。 左帯から出ていくことになるが、探す場所としてはここが自然だと見た。

左帯に並ぶプロジェクトは、閲覧できるものだけである。 非公開プロジェクトでメンバーでないものは表示されない。 ただし組織管理者にはすべて表示される。
