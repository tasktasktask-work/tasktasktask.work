ほかのすべてがここを前提にするので、最初に作った。 パスワードとマジックリンクの併用、10回失敗でのロック、そしてその解除まで。 通しで動くところまで確かめてある。

実装していないのは招待からの登録、 組織管理者による手動のロック解除、SMTP での送信の三つである。

通しで確かめたこと

本物のフォーム送信で、10回失敗させるところから解除まで動かした。

誤ったパスワードで9回      → メールアドレスまたはパスワードが違います
10回目                    → 同じ文言（ここでロックがかかる）
ロック後に正しいパスワード → パスワードでのログインを停止しています
                             ログイン用リンクを受け取ると、その場で解除されます

コンソールに出たメール:
  To: e2e@example.com
  Subject: TASK3 のパスワードログインを停止しました

リンクを開く              → 307 / へ、failed_login_count=0, locked=false
解除後にパスワード        → 303、Cookie 発行（HttpOnly, SameSite=Lax）

マジックリンクの一度きりも確かめた。 同じリンクを二度開くと /login?magic=used へ送られ、 「そのログイン用リンクは使用済みです」と出る。

誰が登録しているかを外から測らせない

パスワードが違うのか、そのアドレスが登録されていないのか。 どちらも同じ文言を返す。

それだけでは足りない。 アカウントが見つからないときに照合を省くと、応答が明らかに速くなる。 文言が同じでも、時間で判別できてしまう。 そのため見つからない場合も、ダミーのハッシュに対して照合を一度走らせる。

マジックリンクの要求も同じで、登録の有無にかかわらず 「送りました」と返す。

テストできる形にするために切り分けた

next/headers を読み込むと試せなくなる

next パッケージには exports の定義が無く、 next/headers は Node の ESM では解決できない。 これを読み込んだファイルは、リクエストの外から動かせない。

最初はセッションの作成が、データベースへの記録と Cookie の設定を一度に行っていた。 この形だと、ロックの解除もトークンの一度きりも試せない。 間違えると締め出しか乗っ取りに直結する部分が、まるごと検査の外に出る。

そこで二つに分けた。

ファイル役割試せるか
session.tsセッションの記録、引き当て、失効試せる
cookie.tsnext/headers との橋渡しだけ試せない

結果として tests/authentication.test.ts に11件を置けた。 スキーマの15件とあわせて26件になっている。

✔ 照合できる / 8文字未満は受け付けない
✔ 10 回連続で失敗するとロックする
✔ 時間では解除されない
✔ 成功したら失敗回数もロックも戻る
✔ 使うとログインでき、セッションが作られる
✔ ロックを解除する
✔ 一度使うと無効になる
✔ 期限が切れていたら使えない / 知らないトークンは使えない
✔ 生の値をデータベースに残さない

import の書き方を決め直した

解決系が三つある。TypeScript、Next（webpack）、そして Node である。 テストは Node が src/ を直接読むため、三つすべてが解決できる形に揃える必要があった。

tsconfig.json の paths による @/ は TypeScript しか知らないので Node が落ちる。 package.json の imports に移した。

拡張子も必ず書く。Node の ESM が補わないためである。 #features/* を .ts と .tsx の配列にする案も試したが、 webpack が後方の候補まで辿らず .tsx のファイルを解決できなかった。 常に拡張子を書くという一本の規則に落ち着いた。 規約に書いた。

途中で見つけた穴

仮実装のリダイレクトが循環していた

/ の仮実装が、ログインしていてもいなくても /login へ送っていた。 一方 /login はログイン済みなら / へ送る。 ログインに成功した瞬間から、二つの画面のあいだを往復し続ける。

ログイン後の着地点を作って解いた。 いまは表示名とログアウトだけの画面で、 組織とプロジェクトを実装したら /o/{slug} へ差し替える。

あとから変えたこと

未認証でも /login へ送らない

最初は未認証なら /login へリダイレクトしていた。 そのURLのままログイン画面を出す形に変えた。

行き先を ?next= で持ち回る必要がなくなる。 /o/acme/p/WEB/t/128 を開いた人は、そのURLでログインし、そのまま着地する。 ブラウザの履歴も汚れない。

戻り先はフォームの hidden 項目で運ぶので、利用者が書き換えられる。 素通しすると、細工したリンクを踏んだ人をログイン直後によそのサイトへ送り込める。 return-to.ts で毎回確かめ、テストで固定した。

/o/acme/p/WEB?tag=bug   → そのまま
https://evil.example.com → /
//evil.example.com       → /
/\evil.example.com       → /
途中に改行を含むもの      → /
/auth/magic?token=...    → /

実際のフォーム送信でも確かめた。 /?tag=bug でログインすると /?tag=bug へ戻り、 細工した戻り先はすべて / になる。

マジックリンクは元のURLへ戻れない

リンクはメールの中にある。どのURLで受け取ったかを覚えるには、 magic_link_tokens に列を足して持ち回る必要がある。 いまは / に着地する。

制御構文のブロックを省略しない

if (!user) redirect('/login'); のような書き方をやめた。 一文でも波括弧で囲む。

省略した形は、あとから一行足すときに壊れる。 波括弧が無いまま二行目を書くと条件の外に出るのに、インデントは揃うので読んでも気づけない。

Biome の style/useBlockStatements で機械的に止めた。 既存の17箇所も直してある。

機能ディレクトリの説明を README.md にした

.gitkeep に説明を書いていたが、読まれることを前提にした文章なので README.md に移した。10機能ぶんある。 対応する docs/features/ のページへのリンクと、 そこに置くもの、守る決まりを書いてある。

テストが終わるのに30秒かかっていた

接続プールを閉じていなかった。 テストは通っているのに、空くまで終了が待たされる。 after() で pool.end() を呼んで 0.3 秒になった。
