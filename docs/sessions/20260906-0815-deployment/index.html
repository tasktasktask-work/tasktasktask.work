デプロイ構成の作り直し

developing

VPS では複数のサービスが動いている。 自前で一式を立てる形から、既にあるものへ相乗りする形へ変えた。 VPS にはソースコードを置かず、ビルド済みのイメージだけを送る。

変わったこと

前後
VPS に置くものソースコード一式compose.yaml と .env と data/attachments
イメージVPS 上でビルド手元でビルドし、VPS のレジストリへ push
振り分けCaddy を自前で立てる稼働中の nginx-proxy へ VIRTUAL_HOST で相乗り
データベースcompose で一緒に立てる稼働中の postgres へ postgres-network 越しに繋ぐ
TLSCaddy が取得Cloudflare が終端。VPS までは平文

Caddyfile と、ルートの compose.yaml は消した。 代わりに deploy/compose.yaml を置いてある。これを VPS へ写す。

マイグレーションをどう流すか

イメージだけを送る形にすると、VPS 側に schema/ も migrations/ も Atlas も届かない。 「アプリを入れ替える前に独立した手順として流す」という規約を、実行する場所が無くなる。

アプリの実行イメージにマイグレーションを同梱する形を採った。

docker compose run --rm app migrate

実行時のイメージに Atlas のバイナリと migrations/ と db/functions.sql を持ち込んでいる。 pg と @node-rs/argon2 は Next の standalone 出力に取り込まれるので、 apply-functions.mjs もそのまま動く。

作業用データベースを本番に向けない

Atlas は差分計算に使うデータベースの中身を、実行のたびに作り直す。 ATLAS_DEV_URL が本番を指したまま実行すると、そこにあるデータが消える。

コンテナの中の migrate は atlas.hcl を経由せず、 --url "$DATABASE_URL" を直に渡している。 apply に作業用データベースは要らないので、渡す口ごと無くした。

手元の pnpm schema:* にも、二つが同じ値なら止まる検査を入れた。

気づいたこと

アップロードが本番でだけ落ちるところだった

nginx の client_max_body_size は既定 1MB である。 添付は1ファイル10MBまで許しているので、そのままなら本番でだけ 413 になる。

開発環境の nginx.conf は 512m を直書きしているため、 手元では通り、本番でだけ落ちる。 試すまで気づけない類の食い違いである。

nginx-proxy はコンテナ側の CLIENT_MAX_BODY_SIZE を読むので、 compose.yaml で 12m を指定した。 10MB ちょうどにしないのは、多部分形式の包みぶんを見込んでいるためである。

Cloudflare と VPS のあいだが平文である

SSL は Cloudflare が終端し、そこから VPS へは平文で届く。 VPS の IP へ直接届く経路があれば、セッションの Cookie もマジックリンクのURLも読める。 X-Forwarded-For も偽装できるので、sessions.created_ip は本物とは限らなくなる。

ファイアウォールで 80 番を Cloudflare の IP 範囲だけに限れば塞げる。 証明書の管理が要らないぶん、経路を暗号化するより手数が少ない。 オリジンまでの経路に記録した。

ボリュームの持ち主

コンテナは node（uid 1000）で動く。 data/attachments がそのユーザーで書けなければ、添付のアップロードだけが失敗する。 画面は動くので、試すまで気づけない。

確かめたこと、まだのこと

イメージのビルドは通った

docker build が通ることを確認した（2026-09-06）。 Atlas の取得も、standalone 出力の取り込みも問題なかった。

まだ動かしていないのは、そこから先である。

手順状態
docker build確認済み。その後の修正を経て再確認
レジストリへの push未確認
docker compose run --rm app migrate 実行したが VPS の CPU が張り付いた。 別サービスに切り出して解決
docker compose up -d と nginx-proxy 越しの疎通未確認
data/attachments への書き込み未確認

最後の行は、画面が動いていても添付のときだけ失敗する形で現れる。 一度アップロードを試すまで分からない。

次にやること

  1. レジストリへ push し、VPS で migrate と up -d を試す
  2. VPS の 80 番が Cloudflare 以外から届くかを確かめる
  3. 権限判定のテストと、組織とメンバーの実装
