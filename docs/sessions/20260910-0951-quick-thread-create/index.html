立てる入口を、一覧の中へ

done

「全角の正規化はどこでやっていますか」を質問として残すのに、いまは別の画面へ移動することになる。 その画面には7つの欄がある。埋めるのは種別とタイトルの2つだけである。

専用の画面を選んだ理由は、半分だけ正しい

立てる画面のコードには、なぜ一覧の中に畳まなかったかが書いてある。

一覧の上に畳んで置かず、専用の画面にしてある。 本文を書く場所が要るためで、数行の入力欄に押し込むと 「あとで本文を足す」前提の空のスレッドが並ぶ。

本文を書く場所が要るのは、そのとおりである。 課題の定義は本文にしか書けず、コメントで代用すると後から読む人が経緯の中を掘ることになる。

ところが、この理由が支えているのは「本文を書ける場所を用意すること」までである。 そこから「立てる前に書かせること」までは、もう一歩ある。 その一歩は、種別によって成り立たない。 課題なら、立てる時点でやることの形が言える。 議論と質問は逆で、何が決まっていないのかが言えないから相談として置く。 スレッドが課題を基本単位に置かなかったのは、まさにその形をしていない話に場所を与えるためだった。 その入口が、本文を先に要求している。

空のスレッドが並ぶ、という心配のほうも、条件が変わっている。 前回のセッションで、本文を直す入口を本文の直下へ移した。 立てた直後に開く画面で、本文の位置に「編集」がある。 以前は、その入口は画面の最下部にあった。

決めたこと

何をどう決めたかなぜ
立てる入口 一覧の app-head と app-tabs のあいだに、種別とタイトルだけの一行フォームを置く 押しボタンを置き換える。押して開く形にすると手数が減らない
立てる画面 /p/{key}/new を消す 入口が一覧と詳細に移ると、この画面を指す導線が無くなる
作成後の行き先 一覧に留まる。種別の選択は残し、タイトル欄だけ空に戻す 3件続けて立てるとき、毎回種別を選び直すことになる
作成の知らせ フォームの下に「WEB-12 を立てました」を出し、番号をリンクにする 絞り込み中は、立てた行が一覧に出ない。本文を書きに行く道も同時に要る
子を立てる導線 詳細の右の欄はいまの文のままにして、押した語で種別が決まるフォームを開く 3語が並んでいるのに、開いた先でもう一度種別を選ばせることになる
親スレッド 属性の表から出し、子スレッドの真上に独立した欄として置く 属性の6行目にあると、詳細を開くまで存在に気づけない
添付を足す 右の欄の一番上へ移す 押す回数が多い。高さが変わらないので、上に積んでも下の欄が動かない
立てる処理 createThread の引数を種別とタイトルと親の3つにする 画面から常に空が渡る引数を5つ抱えることになる
タグの選択欄 TagBoxes.tsx を消す 立てる画面だけが使っていた。タグを付けるのは詳細の TagPicker に一本化する
ガントの空状態 「課題を立てる」をスレッド一覧へのリンクに変える 簡易フォームで立てた課題は期間を持たないので、ガントには出てこない

実物の見え方は修正イメージにある。 一覧の一行、立てた直後、子スレッド欄の開閉、右の欄の並び。

絞り込みの中で立てると、行が出てこない

一覧に留まると決めた時点で、一つ壊れる。 種別が議論のものだけを表示しているときに課題を立てると、立てた行は条件に合わない。 既定では完了とアーカイブ済みも隠しているので、条件を触っていない画面でも起こりうる。

絞り込みを自動で外す案は採らない。 いま見ていた集合が、立てた拍子に消える。 割り振りを決める会議の最中に「未設定だけ」を出しているとして、そこで質問を一つ立てたら一覧が全件に戻る、という挙動になる。

代わりに、フォームの直下へ知らせを出す。

WEB-12 を立てました

番号はリンクで、押すと詳細が開く。 絞り込みの有無にかかわらず常に出すので、「出るはずの行が出ていない」ことを人が判断せずに済む。 残すのは直近の1件だけである。 3件続けて立てたときに知らせが3行積まれると、フォームの位置が下へずれていく。

子スレッドは、押した語が種別になる

詳細の右の欄には、いまこう出ている。

このスレッドを親にして
課題 / 議論 / 質問 を作成する

3つの語はそれぞれ、種別を問い合わせに載せて立てる画面へ飛ぶリンクだった。 行き先が消えるので、その場でフォームを開く形にする。 このとき、開いた先に種別の選択欄を置くと、3語を押した意味が消える。

語そのものを radio にする。 押した語がフォームの type の値になり、選択欄は要らない。 タイトル欄を出す役は CSS が持つ。

/* どれか一つが選ばれるまで、タイトル欄は出ない */
.p-child-new .compose { display: none; }
.p-child-new:has(input:checked) .compose { display: block; }

JavaScript が動かなくても、ラジオを押せば欄が出て、送信できる。 タイトルと本文の書き換えで details と :has() を使ったのと同じ理由で、開閉に JavaScript を要求しない。

立てたあとも、選んだ語は選ばれたままにする。 子の課題を3つ並べるときに、毎回「課題」を押し直すことになるためである。 知らせは出さない。 すぐ上の一覧に行が増えるので、それが結果になる。

親が居る場所

親の付け替えは、いまも詳細の右の欄でできる。 属性の表の6行目、進捗率と担当者とタグと期間の下に「親」という行があり、WEB-3 と打って保存すると輪の検査を通って書き換わる。 この機能を「無い」と受け取られていた。

見つからない理由は二つある。 一つは位置で、属性の表の中では、進捗率や担当者と同じ重みの1行にしか見えない。 もう一つは、いまの親が誰なのかが読めないことである。 欄にあるのは番号だけで、タイトルはパンくずの側にしか出ていない。

表から出して、子スレッドの真上に独立した欄として置く。 見出しは「親スレッド」で、中身は子スレッドの行と同じ形にする。 種別の札、タイトル、番号。 そのすぐ下に、付け替えの入力欄を置く。

並べると、親子が上下の位置関係そのものになる。

添付を足す欄が一番上へ来る。 前回この欄を右へ移したとき、「高さの変わらないものを上に積む」と書いた。 子スレッドは0件から十数件まで伸びるので、下に置く。 添付の欄は高さが固定なので、属性の上へ移しても下の欄の位置は動かない。 理由はそのまま生きている。

親の種別を出すために、詳細を引く問い合わせに parent.type を足す。 親への LEFT JOIN は番号とタイトルのために既にあるので、列が一つ増えるだけである。

立てる処理から、5つの引数が落ちる

いまの createThread は、8つの値を受け取って一度の取引で書く。 種別、タイトル、本文、親、担当者、開始日、終了日、タグ。 簡易フォームが送るのは、このうち3つだけになる。

残りの5つを引数に残すこともできる。 画面から常に空が渡るだけで、実装が二重になるわけではない。 ただ、そうすると読む人が「どこから担当者が渡るのか」を探すことになり、答えは「どこからも渡らない」である。 だから削る。

export type CreateThread = {
  readonly type: ThreadType;
  readonly title: string;
  /** 親のスレッド番号。同じプロジェクトのものに限る。 */
  readonly parentNumber: number | null;
};

本文の列は NOT NULL DEFAULT '' なので、挿入から外すだけで空文字が入る。 期間の検査（checkPeriod）と担当者の在籍の検査（isAssignable）は、それぞれ setPeriod と setAssignee の側に同じものがある。 立てる側から消えるだけで、判定そのものは残る。

通知が一つ、届かなくなる

いまは立てると同時に担当者を指名でき、そのとき assigned の通知が飛ぶ。 指名する欄が消えるので、この道は通らなくなる。 通知そのものは消えない。 立てた直後に詳細で担当者を選べば、setAssignee の側から同じ行が積まれる。 増えるのは、指名までの手数が一つ増えることだけである。

タグとスレッドの輪が、ほどける

コーディング規約に「互いを呼びそうになったら、判定の無い側を切り出す」という項がある。 その実例が、いま消えようとしている。

タグとスレッドがそうだった。スレッドを立てるときにタグを付けるので #features/thread/queries.ts がタグ側を呼ぶ。 一方でタグ側は、書き込みの可否を判定するために THREAD_WRITABLE を読む。

この輪を切るために tag/attach.ts がある。 判定を持たず、行を入れるだけの関数を置いた側である。 tagIds が引数から落ちると、スレッド側からタグ側への呼び出しは一本も残らない。

attach.ts は tag/queries.ts へ畳み戻す。 ファイルとしては死んでいない。 attachTagByName と setThreadTags が呼び続けるので、同じ模組の中の非公開の関数になるだけである。 分けておく理由だけが無くなる。

規約は残す。 実例の側に、いつ輪が消えたのかを書き足す。 子スレッドのフォームにタグを足したくなれば、同じ呼び出しが戻ってくる。 そのときはもう一度切り出すことになり、規約はそのために書いてある。

組んでみて分かったこと

二つあった。どちらも画面と試験を動かすまで見えなかった。

親の入力欄が、素の見た目に戻った。 属性の表の中では .app-props input が大きさと罫を与えていた。 表から出した先にその規則は無いので、ブラウザの既定の入力欄が出る。 .p-parent を新しく置いて、表に居た頃と同じ大きさに揃えた。

詳細画面に「タイトル」の名札が二つになった。 スレッド自身のタイトルと、子として立てるスレッドのタイトルである。 既存のブラウザ試験は前者を getByLabel('タイトル') で拾っていて、 部分一致なので両方に当たるようになった。 試験の側を完全一致へ寄せた。画面のほうは、二つあるのが正しい状態である。

試験

単体は件数が減った。 立てるときの期間と担当者を確かめていた3件は、同じ判定を setPeriod と setAssignee の側で確かめている。 代わりに「立てた直後の本文は空である」を足した。 本文の列を挿入から外したので、既定値が入ることを確かめるものが要る。

試験どうするかなぜ
課題以外は期間を持てない（立てる） 消す 「議論に期間は入れられない」が setPeriod の側にある
期間は片方だけでは入れられない（立てる） setPeriod の側へ移す この形だけ、書き換えの側に無い
組織の外の人は担当者に置けない（立てる） 消す 「組織から外れた人は担当者に置けない」が setAssignee の側にある
立てるときに指名しても届く 消す 指名する欄が無くなる。「設定した相手に届く」は残る
タグを付けたスレッドが一覧に出る 立ててから setThreadTags で付ける形に直す 立てると同時には付けられなくなる

単体は518件から516件になった。E2E は2件足して25件から27件になった。 凍結中の1件は、リンクの不在を見ていたので、タイトル欄の不在を見る形に書き換えた。

  • 一覧で種別とタイトルだけを入れて立てると、画面が変わらずに番号の知らせが出る
  • 詳細の「議論」を押すとタイトル欄が出て、立てると子スレッドの欄に行が増える

絞り込み中に立てた行が一覧に出ないことは、E2E に置かない。 サーバー側で条件を組み立てた結果であり、ブラウザの中でしか起きない壊れ方ではない。

変えないもの

期間と担当者とタグは、詳細でしか入れられなくなる。 立てた直後に開けば、どれも右の欄にある。
