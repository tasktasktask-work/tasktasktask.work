画面の枠を外した

done

幅を止めていたのは max-width: 68rem の一行である。 外すのも一行で済んだ。手が要ったのは、外した後に画面へ出てきたもののほうだった。

止めていた場所は一箇所だった

枠は .app-frame という一つのクラスで、使っているのは組織の一覧、 アカウント、そして組織の中の全画面を包む OrgShell の三箇所である。 つまり実質すべての画面が、68rem の板の上に載っていた。

紛らわしい作りがひとつあった。globals.css にも .app-frame がある。 そちらは高さと並べ方だけを持ち、幅には触れていない。 幅を決めているのは共有スタイルの側だけである。

意匠の正本は docs/theme.css で、そこから src/styles/ へ写している。 だから直す場所は資料の側で、製品はそれを受け取る。 資料のページモックは 60rem の紙面に 52rem の最小幅で置いてあるので、 68rem の上限にはもともと届いていない。見本の見え方は変わらなかった。

決めたこと

何をどう決めたかなぜ
幅 上限を撤廃し、左右の余白も置かない 主役が一覧と工程表であり、横を余らせる理由が薄い
枠線 四辺とも外す 画面の端に張り付いた1pxは、枠ではなく傷に見える。上帯は自分で罫を持っている
読み幅 上限を置かない。本文も一覧もそのまま伸ばす 先に上限を置くと、どこが本当に読みにくいのかが隠れる
左帯とカードの列 現状維持 枠だけを変え、実物を見てから中身を触る
中身の左右余白 現状維持（1.3rem） 業務画面の端としては狭くない
試験 足さない 幅はまた触る値である。共有スタイルの写し漏れは pnpm styles:check が別に見ている

変えた規則

- .app-frame { max-width: 68rem; margin: 0 auto; border: 1px solid var(--rule); background: var(--card); }
+ .app-frame { background: var(--card); }

残したのは背景だけである。 画面が使うクラスの定義は src/styles/ の中にしか探しに行かない検査があるので、 規則ごと消すことはできない。

修正イメージ

前は、地の上に板が浮いていた。1920px の画面では、板の外側に800pxの地が残る。

前 · 1920px

後は、板が地を覆う。左帯の幅も、中身の余白も、そのままである。

後 · 1920px

広げたら、無地の帯が出た

実物を撮って最初に目に入ったのは、ログイン直後の組織の一覧だった。 組織のカードの右に、幅1600pxの無地の帯が寝ている。

原因はカードの並べ方にあった。 .cards は隙間を 1px だけ空け、その隙間から容器の背景を覗かせることで、 カードのあいだに罫を引いていた。容器の背景は罫の色である。 カードの無いセルには何も乗らないので、そこは容器の色がそのまま面で出る。

68rem のころは3セル分だった。列が7つに増えて、面積が倍以上になった。

前 · 組織がひとつのとき

直し方は隣にあった。プロジェクトの一覧は、隙間を .8rem 空けて、 罫はカードごとに持たせている。同じ広い画面でも、こちらは何も起きていない。 .cards をその作りへ寄せた。

後 · 組織がひとつのとき

この並びは資料の側でも使っている。各ページの下にある「関連する場所」がそれである。 そちらも継ぎ目のない板から、離れたカードへ変わった。

工程表は伸びない

広げれば一番得をするのは工程表だと思っていた。実際には伸びなかった。

.p-gantt-grid の横幅は、名前の欄と「日数 × 1.6rem」の和である。 期間が18日しかない図は、画面が1920pxあっても、そのぶんの幅しか使わない。 右におよそ900pxの余白が残る。

これは直さないことにした。 1日の幅が画面や期間で変わると、同じ10日の棒が、別のプロジェクトでは違う長さに見える。 工程表は長さを読む道具なので、そこは動かせない。

確かめたこと

pnpm check  型・整形・共有スタイル・class の定義・移行の検査すべて通過
実画面の撮影 7画面 × 1920/1280 の14枚
  枠の左端 x=0、幅は画面幅と一致、横方向の溢れなし
資料のページ 見本の幅は 60rem のまま変わらず
確かめていないところ

撮ったのは組織の一覧、アカウント、担当スレッド、プロジェクト一覧、 スレッド詳細、ガント、メンバーの7画面である。 ログイン、招待の受け取り、各種の設定画面は撮っていない。 どれも .app-frame の中に載るので、幅の扱いは同じになる。

スマートフォンの幅では、もともと上限に届いていなかった。 変わるのは枠線が消えることだけで、そちらは撮っていない。

払った代金

読み物の幅に上限を置かなかった。 スレッドの本文は1600pxの一行になる。行の折り返しが遠いほど、次の行の頭を見失いやすい。

空の区画と一覧の行も、同じ幅を受け取っている。 「まだありません。」が広い点線の中央に浮き、行の名前と操作は画面の両端に分かれた。 これらは広い画面での間延びに書き出した。 想像で先回りせず、使っていて繰り返し邪魔になったものから直す。
