辞めた人に、非公開プロジェクトが見えていた

done

画面をひとつも作らないうちに、権限の判定だけ先にテストで固めておこうと考えた。 実装が増えてからでは、あとから振る舞いを変えにくくなる。 そのつもりで書き始めたのだが、固める前の振る舞いのほうに穴があった。

判定はどこにあるか

閲覧できるプロジェクトの判定は、 src/lib/db.ts の VISIBLE_PROJECT_IDS という副問い合わせにだけ書いてある。 一覧も詳細もガントも、この一本を IN (...) の中に差し込んで使う。

見るべきものは四つある。 組織に所属しているか、そのプロジェクトが公開か、プロジェクトメンバーか、 組織管理者か。 この四つを各所に書き写すと、どこかで一つ落ちる。 だから一箇所にまとめてある。

まとめてあっても、中では散っていた

直す前の形はこうだった。

WHERE p.organization_id = $1
  AND p.deleted_at IS NULL
  AND (
    (p.visibility = 'public' AND EXISTS (...組織メンバー...))
    OR EXISTS (...project_members...)
    OR EXISTS (...組織管理者...)
  )

三つの枝のうち、一つめと三つめは組織の所属を見ている。 二つめだけが見ていない。

組織から外しても、プロジェクトの行が残っていれば見える

組織からメンバーを外す操作は organization_members.deleted_at を埋める。 project_members の行はそのままである。

すると二つめの枝が通る。 組織を離れた人に、非公開プロジェクトが見え続ける。

実際にそうなるのかを、使い捨ての手順で確かめた。 組織から外した利用者に対して非公開プロジェクトが返ってくる。 推測ではなかった。

直した形

所属の確認を、枝の中から最も外側へ移した。

WHERE p.organization_id = $1
  AND p.deleted_at IS NULL
  AND EXISTS (...組織メンバー...)      -- ここへ出した
  AND (
    p.visibility = 'public'
    OR EXISTS (...project_members...)
    OR EXISTS (...組織管理者...)
  )

「外すときは両方の行を消す」という規律でも塞げる。 ただしその規律は、消す処理を書く人が毎回思い出さないと保てない。 条件の側で成り立たせておけば、思い出さなくてよい。

組織が境界であることを、条件の形で示す

組織はデータの境界である。 境界の確認が、三つある枝のうちの二つに書かれている状態は、 それ自体が「境界ではない何か」に見える。

いちばん外側に一度だけ書くと、読んだ人にも同じ意味で伝わる。

固めた振る舞い

tests/permission.test.ts に14件。 副問い合わせを直接叩くものと、listThreads を通すものの両方を置いた。 副問い合わせが正しくても、使う側が差し込み忘れれば漏れるためである。

群固定したこと
公開プロジェクト組織メンバーには見える。属さない人と別組織の人には見えない
非公開プロジェクトメンバーというだけでは見えない。project_members なら見える。組織管理者は無条件で見える
組織から外れた人公開も見えない。project_members が残っていても非公開は見えない。管理者だった人も見えない
プロジェクトの状態アーカイブ済みは見える。論理削除は組織管理者にも見えない
組織の取り違え複数の組織に属していても混ざらない

あわせて、スコープの isOrgAdmin を true に偽って渡しても結果が変わらないことを固定した。 判定はデータベースの側で行われていて、呼ぶ側の申告では動かない。

テストが本当に落ちるかを確かめた

直したあとに書いたテストは、直したコードに対しては当然通る。 通ることは、漏れを捕まえられる証拠にならない。

そこで直す前の条件へ一時的に戻して、同じテストを流した。

直す前の SQL: 辞めた人に非公開が ★ 見える
直した後の SQL: 辞めた人に非公開が 見えない

落ちることを見てから、元に戻した。

残しておきたいこと

一箇所にまとめたことで安心していた。 まとめた中身が三つに枝分かれしていて、そのうちの一つだけが条件を落としている。 集約したかどうかと、その中が揃っているかどうかは別である。

もうひとつ。 この漏れは、組織とプロジェクトの実装に入る前に見つかった。 この副問い合わせを使う場所が増えたあとでは、直したときの影響を確かめる範囲も広がっていた。
