ガントチャートを描いた

done

最後まで残っていた画面である。見本もあり、決め事も書いてあった。 ところが実装に入ってみると、決めてあったのは「何を出すか」だけで、 「どれを出すか」は一つも決まっていなかった。

決まっていたつもりで、決まっていなかったこと

機能ページには、載るのは課題だけで、アーカイブ済みは出さず、 期間未設定は下の別枠に並べる、と書いてあった。 ここまでは対象ごとの扱いである。

書いていなかったのは、行の集合をどう作るかだった。 期間の無い親に、期間のある子がぶら下がっていたら、親の行は出るのか。 出さないなら子はどこに置くのか。出すなら、下の別枠との関係はどうなるのか。

この一点から、聞き取りは34項目に膨らんだ。

行の集合を一行で決めた

着いた答えは短い。期間を持つ課題と、その祖先。

ここには非対称がある。期間の無い課題でも、子がいれば残る。子がいなければ残らない。 同じ「期間が無い」で扱いが分かれるのは気持ちが悪いが、 落としたときに失われるものが違う。

子のいない課題を落としても、消えるのはその一行だけで、下の別枠が拾う。 親を落とすと、子が一段下がって並んでいる理由が消える。 その子は根の無い行として浮く。

結果として、期間の無い親は図と別枠の両方に出る。 同じ課題が二箇所に現れるのは重複に見えるが、片方は「子がここにいる」ことを、 もう片方は「まだ計画に載っていない」ことを言っている。

見つけた食い違い

どこ食い違いどうしたか
刻み 機能ページは「横軸の刻みは日」。モックには「日 / 週 / 月」の選択肢 日だけにし、モックから選択肢を消した（Q1）
件数の位置 モックは見出しの下。決めたのは図の上の欄 図の上にまとめた。件数は図を読むための数字である（Q27）
タブ モックは「スレッド / ガント / 設定」。実装は「スレッド / メンバー / 設定」 四つ並べ、ガントは見える人全員に出す（Q24）
アーカイブ 用語集は「ガントには絞り込みを切り替えれば表示できる」 ガントに絞り込みは無い。生きた子の親としてだけ残ると書き直した

言葉が二つの意味を持っていた

用例を書いていて気づいた。このシステムでは「畳む」がアーカイブを指す。 コードの注釈でも「畳んだスレッド」「畳んだプロジェクト」と通してある。

ところがガントの行を閉じる操作にも、同じ言葉を当てていた。 ボタンの読み上げは「子を畳む」になっていた。 押すとアーカイブされると読めてしまう。

行を閉じるほうを折りたたみと呼び直し、 画面の言葉は「隠す」「出す」に変えた。用語集にも項を立てて、二つの違いを書いた。

テストが見つけたこと

親を輪にしたデータを与えたら、図が丸ごと空になった。

親を辿って行を集める作りなので、A の親が B で B の親が A だと、 どちらも「親がいる」ことになり、根が一つも見つからない。 親の付け替えでは輪を弾いているので、正しく動いていれば起きない。 それでも、防ぎ漏れたときに何も出ないのは、いちばん困る壊れ方である。

根から辿り着けなかった行を最上位として拾い上げるようにした。 拾い上げがあることを確かめるテストと、輪の外にいる行が巻き込まれないことを確かめるテストを足した。

ミューテーションで分かったこと

判定を28か所で壊し、26か所をテストが捕まえた。 生き残った2つは、どちらもデータベースの制約と重なっていた。

壊したところなぜ落ちないか
期間の組を作るときに終了日を見ない threads_period_paired が両方入るか両方空くかを保証している。 片方だけ入った行はデータベースに存在できない
取得の条件から type = 'kadai' を外す threads_period_only_for_kadai により、期間を持てるのは課題だけ。 期間で絞った時点で議論と質問は落ちている

どちらも二重の守りである。落とせないと分かったうえで残し、 なぜ落とせないのかをコードの注釈に書いた。 制約そのものは tests/schema.test.ts が確かめているので、 守りの根が試されていないわけではない。

捕まえられなかった代わりに、テストの弱さが二つ出た。 週の縞をずらす日数を確かめるテストが、月曜始まりの範囲だけを見ていた。 ずらす日数を 0 に固定しても、月曜なら 0 が正解なので通ってしまう。 上限のテストも、祖先を足して件数が戻る形になっていて、上限を外しても同じ数になっていた。 どちらも書き直した。

自動では確かめていないところ

開いた直後に今日の位置までスクロールする処理は、実物のブラウザでしか動かない。 一日あたりの幅を測ってから送る作りなので、描かれていない状態では長さが0になる。

折りたたみも同じで、押した後の行の消え方は確かめていない。 どの行を隠すかを決める計算そのものは layout.ts の側にあり、そちらは試してある。

名前の欄と目盛りの貼り付き、狭い画面での欄の縮み、 土日の縞と今日の線の位置は、どれもCSSの働きなので、 描画の値が渡っていることまでしか確かめていない。

払った代金

横に伸びる長さに上限を置かなかった（Q9）。 終了日を2126年と打ち間違えると、図は百年ぶんの幅になる。 異様に長いこと自体が合図になる、という判断だが、その課題を探して直すまでは読みにくい図が残る。

絞り込みを置かなかった（Q15）。 課題が300件あるプロジェクトでは、自分の担当だけを見る手段がこの画面に無い。 探すのはスレッド一覧の役目に寄せてある。

期間未設定の枠から日付を入れられない（Q31）。 枠を空にするには、一件ずつ詳細画面へ行って戻ることになる。
