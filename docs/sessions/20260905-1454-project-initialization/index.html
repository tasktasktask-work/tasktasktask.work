スキーマを実データベースで検証した

devcontainer が localhost-postgresql のネットワークに参加しており、 PostgreSQL 18.4 に接続できた。 Atlas を入れ、最初のマイグレーションを生成して適用し、 15テーブルが作られることと、制約が意図どおり効くことを確かめた。

作ったデータベースは tasktasktask_work_local（開発用）と tasktasktask_work_atlas（Atlas の作業用）の二つである。

添付の配信を同一オリジンに変えた

前のセッションでは、添付ファイルを本体とは別のドメインから配信すると決めていた。 この判断を変えた。

実際に守っているのはヘッダである。 Content-Disposition: attachment と nosniff と Content-Type: application/octet-stream が揃っていれば、 HTML をアップロードされてもブラウザは描画せずダウンロードする。

オリジンの分離が足していたのは、この経路に将来手を入れた誰かが間違えたときに被害を抑える、という保険だけである。 そしてその保険には実費がある。 別のドメインにはセッションの Cookie が送られないので、 非公開プロジェクトの添付を誰に見せるかを、 署名付きURLのような別の仕組みで決めることになる。

同一オリジンなら Cookie がそのまま使え、閲覧判定は他の画面と同じ経路で済む。 サービスもドメインも一つ減る。

そのぶん、経路の作り方に三つの条件を付けた。

  • 添付を返す経路を1本に限り、その関数が常にヘッダを付ける。切り替えのパラメータを作らない
  • インライン表示するのは、サーバー側で再エンコードした出力だけ。Content-Type は決め打ちの値から選ぶ
  • レスポンスに Content-Security-Policy: default-src 'none'; sandbox を足す

三つめは、オリジンを分けなくなったぶんの埋め合わせである。 二つめが崩れたときの最後の砦になる。

設計から変えた2点

citext をやめ、拡張を一つも使わない構成にした

まず organizations.slug を text にした。 CHECK 制約の正規表現が小文字と数字しか許さないので、 比較を大文字小文字非依存にする意味がないためである。

そのあと Atlas を流して、無料の範囲では CREATE EXTENSION を扱えないと分かった。 残っていたメールアドレスの citext も text にし、小文字に揃えて保存する。 書き込む側が lower() を忘れたら CHECK 制約で落ちる。

結果として、このプロジェクトは PostgreSQL の拡張をひとつも使わない。

updated_at をトリガで埋めることにした

設計には書いていなかった。 アプリケーション側で毎回書く方式は書き忘れが起きる。

そして書き忘れが見つけにくい。 スレッド一覧の既定の並び順が更新の新しい順なので、 更新したのに一覧で下に沈む、という形でしか表面化しない。

意匠をドキュメントと共有する仕掛け

スタイリングに素の CSS を選んだのは、 docs/theme.css に設計済みの意匠があり、 それをドキュメントと製品で共用したかったからである。

ただし写しを置くと、片方だけを直したときに静かにずれる。 ずれたことに気づく手段がない。 そこで docs/theme.css に @shared の目印を入れ、 同期と照合をスクリプトにした。

pnpm styles:sync    docs/theme.css → src/styles/ へ写す
pnpm styles:check   食い違っていれば失敗する（pnpm check に含む）

共有しているのは、色と書体の変数、製品コンポーネント（種別バッジ、進捗メーター、 ガントバー、ハンコアバターなど）、画面のシェルの三つである。 ドキュメントのページモックと製品の画面は、文字どおり同じ CSS で描かれる。

制約で守れること、守れないこと

守れること手段
親子がプロジェクトをまたがない複合外部キー (parent_thread_id, project_id)
スレッドの組織とプロジェクトの組織が一致する複合外部キー (project_id, organization_id)
議論と質問が期間を持たないCHECK threads_period_only_for_kadai
議論と質問の進捗率が 0 か 100 だけCHECK threads_progress_binary_for_non_kadai
アーカイブを経ないと削除できないCHECK *_delete_after_archive
添付がスレッドかコメントの一方だけに付くCHECK attachments_exactly_one_owner
自分の操作で自分に通知が来ないCHECK notifications_not_self
スレッド番号が組織の中で一意UNIQUE (organization_id, number)
データベースでは守れないもの

次の三つはアプリケーション側で担保する。規約に書き足す必要がある。

  • 親子の循環参照。階層に深さの制限がないため CHECK では表現できない。 親を設定するときに再帰CTEで祖先を辿り、自分自身が現れないことを確認する
  • 最後の組織管理者を外せない。行数の下限は CHECK では書けない
  • プロジェクトキーの変更禁止。形式は CHECK で縛れるが、 「作成後は変えられない」は更新時の判断になる

Atlas を流して分かったこと

無料の範囲では、Atlas は拡張と関数とプロシージャを扱えない。 schema/ に書くと migrate diff の時点で止まる。

これが二つの判断を導いた。 ひとつは上に書いた「拡張を使わない」。 もうひとつは、関数とトリガを db/functions.sql に分け、 マイグレーションの適用後に流すことである。

分けたものを Atlas が消しにいかないかを確かめた。 関数とトリガを手で作った状態で migrate diff を流しても、Atlas は何も生成しない。 読めないものは差分の対象にもならない。

Atlas Pro に移るときは見直す

この扱いが成り立つのは、Atlas が関数を読めないからである。 atlas login をすると Atlas は関数とトリガも差分の対象にし、 schema/ に無いそれらを「消すべきもの」と判断しうる。

atlas migrate lint は使えない

v0.38 から Pro 限定になっている。 生成された移行に危ない変更が混ざっていないかを見る、という役割は残したいので、 scripts/lint-migrations.mjs を自前で書いた。

検査するのはスキーマ移行に書いた規約そのものである。 破壊的な変更、列の型変更、CONCURRENTLY のない索引作成、 NOT VALID のない CHECK 追加、SET NOT NULL。 汎用の検査より、この構成で守りたいことを直接かけるほうが効く。

その移行で新しく作られたテーブルが対象なら見逃す。走査すべき行が無いためである。 承知のうえで通すときは、直前の行に -- lint-ok: 理由 を書く。

スクリプトの不備をひとつ直した

atlas は別のプロセスなので、.env の中身が自動では渡らない。 最初に書いたスクリプトは atlas を直接呼んでいたため、 シェルに環境変数を入れていない状態では sql/sqlclient: missing driver で止まった。

いまは scripts/atlas.mjs を経由し、.env を読んでから起動する。 環境変数が足りないときと atlas が入っていないときは、 それぞれ何をすればよいかを案内して止まる。

制約が効くことをテストで固定した

Q4 で「権限判定と DB 制約に絞ってテストを書く」と決めた分の第一歩として、 実データベースに対する検査を tests/schema.test.ts に置いた。 Node 内蔵のテストランナーを使うので、依存は増えていない。

$ pnpm test
  ✔ 議論と質問は期間を持てない
  ✔ 議論と質問の進捗率は 0 か 100 しか取らない
  ✔ 親子はプロジェクトをまたげない
  ✔ アーカイブを経ないと削除できない
  ✔ スレッド番号は組織の中で通し番号になる
  ✔ 大文字のメールアドレスを受け付けない
  ✔ 添付はスレッドかコメントの一方にだけ付く
  ✔ 自分の操作で自分に通知は作れない
  ✔ updated_at のトリガが古い値を上書きする
  ✔ date 列は文字列として返る
  ...  15 tests / 15 pass

各テストはトランザクションの中で走り、最後に巻き戻す。 後片付けを書かずに済み、テストどうしが干渉しない。

最初に書いたテストは誤っていた

updated_at のトリガを検査するとき、 同じトランザクションの中で pg_sleep を挟んで前後を比べた。 now() はトランザクションの開始時刻を返すので、値は動かない。 トリガは正しく効いていたのに、テストが失敗と判定していた。

いまは「手で入れた古い値が上書きされるか」で見ている。 ひとつのトランザクションで起きた変更が同じ時刻を持つのは、 updated_at の意味として正しい。

  2. 権限判定のテストを足す。VISIBLE_PROJECT_IDS が非公開を漏らさないこと
  3. SMTP の送信実装。依存を決めてから
