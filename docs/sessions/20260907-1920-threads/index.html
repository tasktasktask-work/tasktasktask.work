種別も進捗率も親子も番号の振り方も、仕様は前から書いてあった。 書いていなかったのは、誰が触れるのかである。 機能のドキュメントが名指しで断っていたのは 「削除は組織管理者だけ」の一点だけだった。

見えている人は書ける

三つの案があった。閲覧できる人全員、作成者と担当者だけ、それに管理者を足したもの。 聞いた答えは一つめだった。

操作閲覧できる人組織管理者
立てる●●
タイトルと本文●●
進捗率、担当者、期間、親●●
アーカイブと解除●●
削除●

絞らなかった理由は、履歴を残さない設計と噛み合わないからである。 本文もタイトルも上書きで、残るのは編集済みの印だけにしてある。 そこへ「作成者と担当者だけが直せる」を重ねると、 担当者が休んでいるあいだ、締切ひとつ動かせない。

質問という種別を用意しておきながら、 質問を立てられない人が組織にいる、という形も避けたかった。

プロジェクトのときと線の引き方が違う。 あちらはプロジェクト管理者を作った。 こちらは作らない。プロジェクトの設定は「枠を決める」操作で、 スレッドの書き換えは「中で作業する」操作である。同じ段に置く必要がなかった。

はみ出し警告を、どちらの行に出すか

用語集には「親に表示する印」と書いてあった。 実装しようとして、その通りにはできないことに気づいた。

一覧で親の行に警告が付いていても、ぶら下がった十件のうちどれがはみ出しているのかが分からない。 親を開いて、子を一件ずつ日付で見比べることになる。それでは印の意味がない。

そこで、一覧では子の行に出し、詳細画面では親の側にも出すことにした。 詳細画面なら子が数件ずつ並んでいるので、そこから探せる。用語集もこれに合わせて直した。

判定は親と子の両方に期間があるときだけ行う。 親が期間未設定なら、外側の枠そのものが無い。

はみ出す日付は、入力の時点では止めない

止めると、親の締切を延ばすまで子の日付を入れられなくなる。 どちらを先に直すかまで決めてしまうのは、警告の役目を越えている。

親は番号で打ち込む

プロジェクトのスレッドが数百件になると、選択肢の一覧からは選べない。 WEB-3 でも 3 でも受ける入力欄にした。

ただ、番号を打ち込ませる形は、打ち込まない人を生む。 親子関係は、議論とそこから出てきた課題を結ぶ唯一の手段である。 付け忘れると、両者の関係は失われる。

そこで各スレッドに「関連する課題を作成する」を置いた。 ここから立てると、そのスレッドが親に入った状態で 立てる画面が開く（この画面は 2026-09-10 に廃止した）。 議論を読んでいる最中に課題を立てる、というのがいちばん多い流れになるはずで、 そのときに番号を書き写させない。

問い合わせに書かれた番号は、画面を出す前に一度引く。 引けなければ空の欄で開く。入力欄に入れて開くと、 本文を書き終えてから「その番号はありません」と断ることになる。

輪を作らせない

A の親が B、B の親が A。この状態は CHECK 制約では書けない。 親から上へ辿り、自分が現れたら断る。

WITH RECURSIVE up(id, parent_id, depth) AS (
  SELECT id, parent_thread_id, 1 FROM threads WHERE id = $1
  UNION ALL
  SELECT t.id, t.parent_thread_id, up.depth + 1
    FROM threads t JOIN up ON t.id = up.parent_id
   WHERE up.depth < 50
)
SELECT 1 FROM up WHERE id = $2

確かめてから書くまでには隙間がある。 そこに別の付け替えが通ると、二つとも単独では輪を作らないのに、 合わせると輪になる。 辿るところと書くところを同じトランザクションに入れ、 親の行を FOR UPDATE で掴んでから辿ることにした。

畳んだプロジェクトの中身を、どこで止めるか

プロジェクトを畳んでも、中のスレッドの archived_at は埋めない。 埋めると、プロジェクトを戻したときに、元から畳んであったスレッドまで開いてしまう。 これは前のセッションで決めたことである。

その帰結として、書き込みの条件は二つの列を見なければならない。 スレッド自身の archived_at と、projects.archived_at の両方である。 片方だけを見ると、畳んだプロジェクトの中身が書き換えられる。

この条件を関数ごとに書き写すと、どれか一つで片方が抜ける。 一つの断片にまとめ、書き込む問い合わせはすべてそれを埋め込む形にした。

const WRITABLE = `t.organization_id = $1
        AND t.deleted_at IS NULL
        AND t.archived_at IS NULL
        AND t.project_id IN (${VISIBLE_PROJECT_IDS})
        AND EXISTS (SELECT 1 FROM projects wp
                     WHERE wp.id = t.project_id AND wp.archived_at IS NULL)`;

通らなかった理由を返す

更新が0行だったとき、それだけでは何が起きたのか分からない。 見えていないのか、畳んであるのか、プロジェクトごと凍っているのか。 画面に出す言葉が変わる。

0行だったときにだけ、もう一度読んで理由を確かめている。 通る経路では余分な問い合わせが増えない。

時刻を、組織の時計で書き出す

スレッドは、時刻を画面に出す最初の機能だった。

toLocaleString() をそのまま呼ぶと、サーバの時計で書き出される。 一台のサーバが複数の組織を捌くので、全員に同じ壁掛け時計を見せることになる。 src/lib/datetime.ts を足し、 組織のスコープが運んでくるタイムゾーンを渡す形にした。 規約にも書き足した。

date 列はこの変換を通さない。 '2026-09-08' という文字列のまま来ており、一度 Date にした時点でずれる。

絞り込みの札を、同じ向きに揃えた

見本の画面では「完了を隠す」がチェック済み、「アーカイブ済みを表示」がチェックなしだった。 既定の見え方は正しいが、二つの札が逆を向いている。 チェックを入れたときに何が起きるのかを、毎回読み直すことになる。

「完了も表示」「アーカイブ済みも表示」に揃え、どちらもチェックなしを既定にした。 見本の側も直した。

絞り込みは JavaScript を使っていない。選んで押せば画面が引き直り、状態は URL に残る。 絞り込んだ結果をそのまま人に渡せる。

今回は出さなかったもの

コメント、タグ、ウォッチ、添付。どれも別の機能として作っていない。 見本の画面には並んでいるが、実際の画面には欄ごと出していない。 押しても何も起きない札を先に置くと、動かないのか壊れたのかが区別できない。

本文の書式も出していない。 Markdown を解釈すると文字列が HTML になり、無害化の責任がこちらに移る。 同じ仕組みをコメントでも使うので、 そちらと一緒に入れることにした。 いまは改行だけが残る。
