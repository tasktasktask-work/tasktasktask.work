スレッドを基本単位に置いた
課題管理のつくりかた

課題として書けるほど固まっていない相談を、どこに置けばいいのか。 多くの課題管理ツールでは、そういう話は課題の欄に無理やり収めるか、チャットへ流れて消えていく。 このプロダクトは、その置き場所をつくるところから設計をはじめた。

名称

プロダクト名は TASK3、ドメインは tasktasktask.work である。 名前の 3 は、スレッドが持つ三つの種別 （課題、議論、質問）と読み合わせられる。 ロゴの意匠はこの読みを使っている。

このプロダクトの骨格

基本単位は課題ではなくスレッドである。 スレッドは三つの種別を持ち、そのうちのひとつが課題にあたる。 残りの二つは、実装のゴールが決まっていない議論と、答えが返れば済む質問である。

三つとも同じ形をしているので、同じ一覧に並び、同じように親子でつながる。 議論の下に課題をぶら下げることも、課題の下に質問を置くこともできる。 違うのは、課題だけが期間を持ちガントチャートに載る、という一点である。

状態を進捗率ひとつに絞ったこと、階層の深さを制限しなかったこと、プロジェクト間の移動を認めなかったこと。 こうした判断は、どれも何かを捨てて何かを取っている。 捨てたもののうち後で拾い直す可能性があるものは、先送りした課題に理由とともに書いてある。

どこから読むか

  1. 用語集
    この製品は既存ツールを下敷きにしていない。 「スレッド」も「進捗率」も他所とは意味が違うので、まずここを読む。
  2. 機能
    画面と振る舞いを機能ごとにまとめてある。何がどう動くかはここでわかる。
  3. データベース
    テーブルの関係と、なぜその形なのか。実装に入る前に読む。
  4. UI設計方針
    画面を作り足すときに、既存と食い違わせないための基準。
  5. 開発と運用
    技術選定、スキーマの移し方、デプロイの構成、コードの書き方。
