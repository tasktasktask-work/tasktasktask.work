Feature 09

ガントチャート

プロジェクト一つぶんを一枚に描く。横軸の刻みは日。バーはドラッグできない。 そして、期間が入っていない課題こそ、この画面がいちばん見せるべきものである。

描く範囲

一枚に描くのはプロジェクトひとつぶんである。 組織の全課題を並べても、数万件では読めるものにならない。

載るのは課題だけである。 議論と質問は期間を持たないので、時間軸には置けない。 親子のツリー上には現れるが、期間の計算からは外れる。

対象扱い
進捗率が 1 から 99 の課題通常のバー。進捗ぶんを塗り分ける
進捗率が 100 の課題薄く表示する
アーカイブ済みの課題表示しない
期間未設定の課題図の下に別枠で並べる
議論と質問行としては出さない

行は階層で並べる

スレッド一覧は平らに並べるのに、ガントは入れ子にする。 同じデータを二つの画面で違う形に見せることになるが、これは目的の違いによる。

一覧は探すための画面である。担当者で絞るとき、階層は邪魔になる。 ガントは計画の構造を読むための画面である。 親の期間と子の期間の関係は、入れ子で並んでいなければ読み取れない。

親の行は折りたためる。

上の図で、いちばん上の行が親である。 子の「検索UIの実装」が親のバーの右端を越えているため、親に警告の印が出ている。

期間未設定を隠さない

開始日と終了日が入っていない課題は、時間軸に置けない。 だからといって表示から外すと、ガントに載っていない課題があること自体に誰も気づけなくなる。

そこで図の下に別枠のリストとして並べる。 この一覧が空になっていれば、プロジェクトの全課題が計画に載っているという意味になる。

はみ出し警告

子の期間が親の期間の外に出ているとき、親の行に印を出す。 該当する子のバーも色を変える。

システムは日付を書き換えない。 親子関係に集計の意味を持たせていないためである。 親の締切を延ばすのか、子を前倒しするのかは人が決める。

読み取り専用にした理由

バーをドラッグして期間を変えることはできない。 期間の変更はスレッドの詳細画面から行う。

ドラッグ編集は、見た目の割に実装が広い。 楽観的な画面更新、他の人の変更との衝突、スナップの単位、タッチ操作。 これらが一度に必要になる。

まず「見る」機能を完成させ、実際に使われてから編集を検討する。 検討の記録はガントの拡張に置いた。
