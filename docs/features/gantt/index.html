Feature 09

ガントチャート

プロジェクト一つぶんを一枚に描く。横軸の刻みは日。バーはドラッグできない。 そして、期間が入っていない課題こそ、この画面がいちばん見せるべきものである。

描く範囲

一枚に描くのはプロジェクトひとつぶんである。 組織の全課題を並べても、数万件では読めるものにならない。

載るのは課題だけである。 議論と質問は期間を持たないので、時間軸には置けない。 行としても出さない。

対象扱い
期間を持つ課題バーを描く。進捗ぶんを塗り分ける
その祖先期間が無くても、畳んであっても行として残す
進捗率が100の課題薄く表示する
アーカイブ済みの課題生きた子の親としてだけ残す。バーは中抜き
期間未設定の課題図の下に別枠で並べる
議論と質問行としては出さない

図に出る行の決め方

行の集合を決める規則は一行で書ける。 期間を持つ課題と、その祖先である。

この規則には非対称がある。 期間の入っていない課題でも、期間を持つ子がぶら下がっていれば図に残る。 一方、子を持たない期間未設定の課題は図に出ない。 同じ「期間が無い」でも、扱いが分かれる。

分けているのは、行を落としたときに何が失われるかが違うためである。 子のいない課題を落としても、失われるのはその一行だけで、下の別枠が拾う。 親を落とすと、子のインデントの根拠が消える。 一段下がって並んでいる理由が読めなくなり、その子は根の無い行として浮く。

期間の無い親は、図と別枠の両方に現れる。 同じ課題が二箇所に出るが、それぞれが言っていることは違う。 図の行は「子がここにぶら下がっている」ことを示し、別枠の行は「まだ計画に載っていない」ことを数え上げている。

行は階層で並べる

スレッド一覧は平らに並べるのに、ガントは入れ子にする。 同じデータを二つの画面で違う形に見せることになるが、これは目的の違いによる。

一覧は探すための画面である。担当者で絞るとき、階層は邪魔になる。 ガントは計画の構造を読むための画面である。 親の期間と子の期間の関係は、入れ子で並んでいなければ読み取れない。

同じ階層の中では、開始日の早い順に並べる。 同じなら終了日の早い順、それも同じなら課題番号の若い順。 期間を持たない行は、その階層の末尾に置く。

親の行は折りたためる。 畳んでも親のバーは変わらない。閉じたかどうかでバーの意味が変わってはいけない。

親が議論や質問だったとき

親子は同じプロジェクトに閉じるが、種別の制限は無い。 課題の親が議論になることがある。

その議論は行として出せない。 かといって、行の無い親のぶんだけインデントを下げると、なぜ下がっているのかが読めない。 そこで、その課題を最上位に上げる。

ただし上げただけでは、親から外れて見える理由が伝わらない。 名前の横に親の番号を小さく添えて、たどれるようにしてある。

横軸

刻みは日である。週や月には切り替えられない。 刻みを増やすと、バーの端をどちらに丸めるか、はみ出しが一マスの中に隠れたときにどう見せるか、 今日の線をどこに引くかが、刻みごとに別の判断になる。

広い範囲は、刻みではなく横軸の範囲で受ける。 実際に描く課題の最も早い開始日から最も遅い終了日までを取り、今日がその外なら今日まで伸ばす。 一日あたりの幅は固定で、長くなったぶんは横へスクロールする。

月を単位に切る案は採らなかった。 三か月のプロジェクトでは、親のバーが常に画面の外へ切れる。

上限を設けなかったこと

終了日を2126年と打ち間違えると、図は百年ぶんの幅になる。 切り詰める案もあったが、採らなかった。 異様に長いこと自体が打ち間違いの合図になり、直す先は詳細画面にある。 日のマス目と土日の縞と今日の線は行ごとの要素ではなく背景で描いてあるので、 伸びても要素の数は行数ぶんしか増えない。

土日は色を変える。祝日は扱わない。 祝日の一覧は国ごとに違い、毎年更新が要る。組織にタイムゾーンの設定はあるが、国の設定は無い。 ここで日本の祝日を焼き付けると、後から外せなくなる。

名前の欄と目盛りを貼り付ける

図は横に長くなる。右へスクロールすると左端の課題名が流れて消える。 そこで名前の欄は左に、目盛りは上に貼り付けて動かさない。

狭い画面では名前の欄が場所を食う。 幅に応じて欄を縮め、入りきらないものから落とす。 落とす順は、担当者の判子、アーカイブ済みの印と親の番号、である。 最後まで残すのは課題名とはみ出し警告にしてある。 警告は、この画面がいちばん伝えたいことの一つである。

期間未設定を隠さない

開始日と終了日が入っていない課題は、時間軸に置けない。 だからといって表示から外すと、ガントに載っていない課題があること自体に誰も気づけなくなる。

そこで図の下に別枠のリストとして並べる。 並ぶのは、終わっておらず、畳まれておらず、期間の入っていない課題だけである。 終わった課題をここに出しても、もう計画に載せる先が無い。

この一覧が空になっていれば、動いている課題はすべて計画に載っているという意味になる。 逆に件数が増えていくなら、計画されないまま溜まっている作業があるということである。

この枠から日付を入れられるようにはしていない。 バーが掴めないのに下の枠では書ける、という不揃いを作らないためである。 課題名は詳細画面へのリンクになっている。

はみ出し警告

子の期間が親の期間の外に出ているとき、親の行に印を出す。 該当する子のバーも色を変える。

見るのは直接の親だけである。 孫が祖父の期間を越えていても、親の期間に収まっていれば印は出ない。 連鎖してはみ出しているなら各段に印が出るので、辿れば発生源に着く。 すべての祖先に印を出すと、根の行に印が集中して、どこで起きたのかが読めなくなる。

親と子のどちらかに期間が無い組は判定しない。 期間が入っていないことは下の別枠が伝えるので、警告と役割を分けてある。

システムは日付を書き換えない。 親子関係に集計の意味を持たせていないためである。 親の締切を延ばすのか、子を前倒しするのかは人が決める。

件数の読み方

図の上に「32件のうち 期間あり 28件」と出す。 分母は畳まれていない課題で、終わったものも含む。畳んだものは含めない。

畳んだものを分母から外しているのは、図にも別枠にも出ないものを数えても、 その差が何をすれば埋まるのかを指さないためである。 分母と分子の差が、そのまま下の別枠の件数に近づく形にしてある。

数の上限

一枚に描く課題は500件を目安にする。 切るのは期間を持つ課題の側だけで、その祖先は順位に関わらず残す。 親だけが落ちると枝ごと意味を失うので、上限は目安として扱い、超えたことを画面に出す。

下の別枠は100件で切る。 この枠の役目は「載っていないものがあると気づかせること」なので、全部並べる必要が無い。 超えたぶんは数だけを出し、スレッド一覧の絞り込みへ送る。

絞り込みを置かない

担当者やタグで絞る欄は置いていない。 絞ると、条件に合わない親が消えて子だけが残る。 その子をどこに置くかを、また決めることになる。

上の欄にあるのは、件数と描いている範囲と、今日へ戻るための一つだけである。

読み取り専用にした理由

バーをドラッグして期間を変えることはできない。 期間の変更はスレッドの詳細画面から行う。 掴めないことを見た目でも伝えるため、リンクにしてあるのは課題名だけにしてある。

ドラッグ編集は、見た目の割に実装が広い。 楽観的な画面更新、他の人の変更との衝突、スナップの単位、タッチ操作。 これらが一度に必要になる。

まず「見る」機能を完成させ、実際に使われてから編集を検討する。 検討の記録はガントの拡張に置いた。
