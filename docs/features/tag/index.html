Feature 07

タグ

親子関係は階層という一本の軸しか表せない。 bug や 要相談 のように、階層と直交する分類はそれでは表せない。 タグはその軸を足すためにある。

親子では代わりにならない

無制限の親子関係があれば、大きな塊の下に小さな作業を並べられる。 「v1.0リリース」という親を立てれば、マイルストーンの役割も果たせる。 実際、そのためにマイルストーンという別概念は用意しなかった。

しかし frontend という分類は、階層のどこにも属さない。 親を frontend にすると、その課題は他の親を持てなくなる。 タグは何個でも付けられるので、この軸を扱える。

組織の単位で定義する

タグはプロジェクトごとではなく組織ごとに定義し、プロジェクトをまたいで共通に使う。 bug や 要相談 のような分類は、プロジェクトが変わっても同じ意味で使われるからである。

誰でも新しいタグを作れる。 作成を管理者に限ると、必要なタグが作れないまま使われなくなる。

見込んでおくこと

組織単位かつ誰でも作成可という組み合わせは、タグが増え続けることを意味する。 選択肢に数十個が並ぶ状態は起こりうる。 その数を前提に、付ける欄は名前を打つ形を主にしてある。 統合と、未使用の一括削除は入れていない。

見え方

bug赤
設計藍
frontend緑
要相談黄
保留灰

色は円形の小さな点で示し、文字色は変えない。 タグの色数が増えても文字の可読性が落ちないようにするためである。 色だけで意味を伝えないので、色覚の違いによる読み取りの差も生じない。

作るのは一箇所だけ

新しいタグを作れるのはタグの管理画面だけである。 /o/{slug}/tags にあり、組織のメンバーなら誰でも入れる。

組織の設定の中には置かなかった。あの画面は組織管理者以外に 404 を返す。置いた時点で「タグは管理者のもの」になり、誰でも作れるという決まりと食い違う。

付ける欄で作れる形も考えた。名前を打つ欄があるので、 一覧に無い名前をそのまま新しいタグにするのは自然に見える。やめたのは、 打ち間違いがそのまま新しいタグになるからである。 backend と bakcend が並んだ時点で、 組織で共通に使うという前提が壊れる。一覧に無い名前は断り、管理画面へのリンクを添える。

付ける

スレッド詳細の属性欄には、三つの入り口がある。 付いている札それぞれの×、名前を打って足す欄、そして畳んだチェックの一覧である。

打つ側を主にしてあるのは、タグが数十個まで増えうるからである。 その数のチェックボックスを常に開いておくと、属性欄が縦に伸びて、 進捗率も期間も画面の外へ出る。畳んでおけば、 進捗率と期間の位置が動かない。

名前を打つ欄は datalist で補助する。 補助であって制限ではないので、一覧に無い名前も送れてしまう。 届いた側で断ることになるのはそのためである。

スレッドを立てるフォームには、チェックの一覧だけを置く。 立てる時点では「一つ足す」という操作が存在せず、送るのは常に選んだ全体になる。

選択肢の範囲が二つある

付ける側には組織のタグをすべて出す。 絞り込みには、そのプロジェクトで実際に使われているタグだけを出す。

絞り込みは「あるものを探す」、付けるのは「無いものを足す」で、要る範囲が逆になる。 付ける側を使用中のものに限ると、作ったばかりのタグをそのプロジェクトへ最初に付ける道が無くなる。 絞り込みに全部を並べると、選んでも常に0件になる選択肢が並ぶ。

色は見本から選ぶ

色は八つの見本から選ぶ。自由な色は選べない。

データベースの制約は #rrggbb の形しか見ないので、 そのままなら背景に沈む色も保存できる。 ところが色は円形の小さな点でしか出ないため、薄い色を選ばれると点が消えたのと同じ見え方になる。 見本は、既に配色が持っている五色に同じ調子の三色を足したものである。

選ぶ形はラジオボタンで、丸をそのまま押させる。 select に色名を並べる案もあったが、それだと選ぶ前に色が見えない。 「浅葱」がどの色かを覚えている人だけが選べる欄になる。

消すと結びも消える

タグを消すと、付いていたスレッドとの結びも一緒に消える。取り消せない。

結びを残す案もあった。残せば、消したことを取り消せる。 ただし同時に、同じ名前で作り直したら半年前のスレッドが一斉にタグ付きで現れるという道もできる。 消したのを取り消したい人と、同じ名前で始め直したい人が、同じ操作をすることになる。

そのぶん、消す押しボタンは二度押しにしてある。 一度目は「128件のスレッドから外れます。もう一度押すと消えます」と文言が変わるだけで、何も起きない。 確認の窓を出す案は採らなかった。窓は押し慣れると読まれなくなるが、 押しボタン自身の文言が変われば、押した手のほうが「変わった」ことに気づく。

使用数は見えない範囲まで数える

管理画面に出る使用数は、組織のすべてのスレッドを数える。 自分に見えない非公開プロジェクトのぶんも含む。

見える範囲に絞ると、消したときに実際に外れる行数より少ない数を見せることになり、歯止めとして働かない。 引き換えに、非公開プロジェクトでそのタグがどれだけ使われているかが数として見える。 分かるのは件数だけで、何のスレッドかは出ない。

名前は変えられる

管理画面では名前と色を変えられる。付いているスレッドはそのまま付いたままになる。

変えられないままにすると、打ち間違えたタグは消して作り直すしかない。 結びは消すときに一緒に消えるので、作り直しでは付け直す手掛かりが何も残らない。 数十件のスレッドを人が思い出して付け直す話になる。

消したタグの名前は、あとからもう一度使える。 一意の索引は生きている行だけを見るためである。 そのとき起きるのは新しい行の挿入であって、消した行が戻るのではない。 結びは既に消えているので、戻したところで中身は空になる。

絞り込みでの役割

全文検索を持たない構成では、スレッド一覧の絞り込みが探すための唯一の手段になる。 タグはその軸のひとつとして働く。

また、進捗率だけでは表せない「却下」や「保留」を、 タグで示すという運用も選べる。 この判断は各組織に委ねている。
