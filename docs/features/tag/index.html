Feature 07

タグ

親子関係は階層という一本の軸しか表せない。 bug や 要相談 のように、階層と直交する分類はそれでは表せない。 タグはその軸を足すためにある。

親子では代わりにならない

無制限の親子関係があれば、大きな塊の下に小さな作業を並べられる。 「v1.0リリース」という親を立てれば、マイルストーンの役割も果たせる。 実際、そのためにマイルストーンという別概念は用意しなかった。

しかし frontend という分類は、階層のどこにも属さない。 親を frontend にすると、その課題は他の親を持てなくなる。 タグは何個でも付けられるので、この軸を扱える。

組織の単位で定義する

タグはプロジェクトごとではなく組織ごとに定義し、プロジェクトをまたいで共通に使う。 bug や 要相談 のような分類は、プロジェクトが変わっても同じ意味で使われるからである。

誰でも新しいタグを作れる。 作成を管理者に限ると、必要なタグが作れないまま使われなくなる。

見込んでおくこと

組織単位かつ誰でも作成可という組み合わせは、タグが増え続けることを意味する。 選択肢に数十個が並ぶ状態は起こりうる。 整理の仕組み（統合、リネーム、未使用の一括削除）は初期リリースに含めていない。

見え方

タグTagChip
bug赤
設計藍
frontend緑
要相談黄
保留灰

色は円形の小さな点で示し、文字色は変えない。 タグの色数が増えても文字の可読性が落ちないようにするためである。 色だけで意味を伝えないので、色覚の違いによる読み取りの差も生じない。

絞り込みでの役割

全文検索を持たない構成では、スレッド一覧の絞り込みが探すための唯一の手段になる。 タグはその軸のひとつとして働く。

また、進捗率だけでは表せない「却下」や「保留」を、 タグで示すという運用も選べる。 この判断は各組織に委ねている。
