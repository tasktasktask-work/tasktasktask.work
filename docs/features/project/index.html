Feature 03

プロジェクト

プロジェクトはスレッドを入れる箱である。 ただの箱ではない。ガントが一枚に描く範囲、メンションの候補に出る人の範囲、閲覧できる人の範囲。 このシステムのいくつもの境界が、同じ一本の線で引かれている。

境界としてのプロジェクト

プロジェクトが引く線を並べると、それが単なる分類でないことがわかる。

何の境界か意味
閲覧範囲非公開に設定すると、メンバーと組織管理者しか見られない
ガントの範囲ガントチャートはプロジェクト一つぶんを一枚に描く
メンションの候補そのプロジェクトを閲覧できる人だけが候補に出る
親子関係の範囲親と子は必ず同じプロジェクトに属する

公開と非公開

公開プロジェクトは組織のメンバー全員が見られる。 非公開プロジェクトは、メンバーに加えられた人と組織管理者だけが見られる。 設定は後から切り替えられる。

非公開から公開への切り替えには確認をはさむ。 戻すことはできても、見られた事実は戻せないからである。

プロジェクト管理者

非公開プロジェクトのメンバーを追加したり外したりできる人をプロジェクト管理者と呼ぶ。 できることはこの一点だけで、スレッドの操作について一般メンバーとの差はない。

プロジェクトを作った組織管理者が自動的に管理者になる。 加えて、すべての組織管理者が全プロジェクトの管理者として扱われる。 メンバーが退職者しかいないプロジェクトを引き継げなくなる事態を避けるためである。

組織から外れたら、何も見えない

閲覧の判定はまず組織の所属を見る。 所属が切れていれば、プロジェクトのメンバー行が残っていても 非公開プロジェクトは見えない。

組織からメンバーを外すとき、プロジェクト側の行まで消し忘れることはありうる。 そこに頼らずに済ませている。 判定の詳細を参照。

プロジェクトキー

半角の英大文字と数字で2文字から10文字。組織の中で重複しない。 スレッド識別子の前半になる。

後から変更できない。 WEB-128 として議事録やコミットメッセージに書かれたものが、ある日から FRONT-128 になると、過去の記録との照合ができなくなる。

キーが変わっても壊れない部分

スレッド番号は組織の中で通し番号になっている。 つまり 128 という数字だけでスレッドは一意に定まり、キーは表示のための飾りにすぎない。 そのため技術的には変更しても壊れないが、人の記憶と記録が壊れるので許可しない。

プロジェクトが持つもの

項目内容
名前画面に出る名称。変更できる
キー2から10文字。作成後は変更できない
説明文何のためのプロジェクトかを書く。変更できる
公開設定公開か非公開。切り替えられる
アーカイブ状態畳んだかどうか

期間は持たない。 プロジェクトの期間を知りたければ、中の課題の日付を見ればわかる。 同じ情報を二か所に持つと、必ず食い違う。

アーカイブと削除

プロジェクトをアーカイブすると、配下のスレッドがまとめて読み取り専用になる。 個々のスレッドのアーカイブ状態は書き換えず、プロジェクト単位で凍結する。 解除すれば元どおり編集できる。

削除は論理削除で、組織管理者だけが行える。 アーカイブを経ていないプロジェクトは削除できない。

移動できないことの帰結

スレッドを別のプロジェクトへ移すことはできない。 置き場所を間違えたら、正しいプロジェクトで立て直し、元のスレッドをアーカイブすることになる。

この制約があるため、プロジェクトをどう切るかは最初に慎重に決める必要がある。 移動を認めるかどうかはスレッドの可変性に記録した。
