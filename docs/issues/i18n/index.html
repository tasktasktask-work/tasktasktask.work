多言語対応

概要

organizations は language と timezone の列を持つが、 取れる値は日本語と Asia/Tokyo だけである。 CHECK 制約で他の値を拒否している。

先送りとした理由

画面の文字列をすべて外部化する作業は、後から入れると全画面に触れることになる。 それは承知のうえで、初期リリースの範囲から外した。 列と設定の枠だけは最初から持たせてあるので、 スキーマの変更なしに値を増やせる。

日付の扱いも、この判断を見込んで決めてある。 課題の期間は date 型で時刻を持たない。 時刻を持つと、組織のタイムゾーンを変えた瞬間に既存の日付が前後する。 日付だけなら、その事故が構造的に起きない。

再検討のきっかけ

  • 日本語以外を使う組織が顧客になったとき
  • 日本国内でも、時差のある地域に拠点を持つ組織が入ったとき

実装するとしたら

まずタイムゾーンから対応する。言語より影響範囲が狭い。

organizations_language_supported の CHECK を緩め、 表示のたびに timezone で変換する処理を通す。 期間が日付型なので、変換が要るのは コメントの投稿時刻と通知の時刻だけである。

言語は、文字列を外部化したうえで翻訳を用意する。 ユーザーが入力した内容（スレッドのタイトル、コメント、タグ名）は翻訳しない。 翻訳するのは画面の固定文言だけである。
