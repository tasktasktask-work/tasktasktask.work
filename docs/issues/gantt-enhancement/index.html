ガントの拡張

概要

読み取り専用のガントチャートは2026年9月8日に実装した。 残して先送りにしたのは、書き込みに関わる二つである。

  1. バーのドラッグによる期間変更。現状は読み取り専用で、変更は詳細画面から行う
  2. 課題間の依存関係。先行と後続を線でつなぐ表示がない

先送りとした理由

ドラッグ編集

見た目の割に実装が広い。必要になるものを並べると次のとおりである。

  • 操作中の楽観的な画面更新と、保存失敗時の巻き戻し
  • 他の人が同時に変更したときの衝突の解決
  • スナップの単位（日単位で吸い付くか、自由に置けるか）
  • タッチ操作への対応

まず「見る」機能を完成させ、実際に使われてから判断することにした。

依存関係

線を引くこと自体は難しくない。 難しいのは、その線に何を意味させるかである。

先行課題の日付がずれたとき、後続を自動で動かすのか。 動かすなら、連鎖してプロジェクト全体の日付が書き換わりうる。 動かさないなら、線は単なる注記になる。

さらに、親子関係には集計の意味を持たせないと決めている。 親の期間は子から計算せず、はみ出しは警告するだけである。 ここに自動で日付を動かす仕組みを足すと、方針が二つに割れる。

再検討のきっかけ

  • 期間の変更が頻繁に行われ、詳細画面への往復が負担になっているとき（1）
  • 「この課題が終わらないと次が始められない」という関係を、本文やコメントで書いて管理しはじめたとき（2）

実装するとしたら

2 は中間テーブルを作る。

CREATE TABLE thread_dependencies (
  predecessor_id uuid NOT NULL REFERENCES threads(id),
  successor_id   uuid NOT NULL REFERENCES threads(id),
  PRIMARY KEY (predecessor_id, successor_id),
  CONSTRAINT no_self CHECK (predecessor_id <> successor_id)
);

循環の検出は親子関係と同じく再帰CTEで行う。 自動でずらすかどうかは、実装より先に方針を決める。 親子の扱いと一貫させるなら、線は引くが日付は動かさない、が筋になる。
