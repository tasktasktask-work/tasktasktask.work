ウイルススキャン

概要

添付ファイルの形式を制限しない構成にしたため、 マルウェアの受け渡しに使える。

配信の仕方（常にダウンロード、種別を推測させない、スクリプトを禁じる）でブラウザ上での実行は防いでいるが、 利用者が自分でダウンロードして開くことは止められない。

先送りとした理由

拡張子やマジックバイトによる検査を廃止したのは、それが役に立たないと判断したためである。 zip に入れれば通り、拡張子を変えれば通る。 守れないものを守っているように見せる仕組みは、判断を誤らせる分だけ有害である。

正しい道具はウイルススキャンだが、これは運用のコストを伴う。

  • ClamAV のコンテナを常駐させる（メモリを1GB前後使う）
  • 定義ファイルの更新を定期的に走らせる
  • スキャン中のファイルをどう扱うか決める（保留にするか、先に見せるか）
  • 検出時の通知と隔離の手順を作る

単一のVPSで動かす構成では、この常駐が資源を圧迫する。 そして社内で使う道具である以上、外部から不特定多数がファイルを送り込む経路がない。 組織のメンバーだけがアップロードできるので、危険の度合いは公開サービスとは違う。

再検討のきっかけ

  • 組織の外部の人（業務委託など）が日常的に添付を送るようになったとき
  • 顧客のセキュリティ要件として求められたとき
  • アカウントの乗っ取りが実際に起きたとき

実装するとしたら

アップロード直後は保留状態にし、スキャンが済むまでダウンロードさせない。

-- attachments に足す
scan_status text NOT NULL DEFAULT 'pending'
  CHECK (scan_status IN ('pending', 'clean', 'infected', 'error')),
scanned_at  timestamptz

pending のあいだは画面に「確認中」と出す。 infected は削除せず残し、組織管理者にだけ見せる。 何が送られたかを後から調べられるようにするためである。
