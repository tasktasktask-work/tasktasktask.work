Issue · 優先度 高

全文検索

概要

スレッドのタイトル、本文、コメントを対象とした検索がない。 探す手段はスレッド一覧の絞り込みだけである。

絞り込める軸絞り込めないもの
種別、担当者、タグ、進捗率、アーカイブ状態本文やコメントに書かれた言葉

先送りとした理由

日本語の全文検索は、英語と比べて手数が多い。 分かち書きが必要で、表記のゆれ（全角と半角、カタカナとひらがな、送り仮名）を吸収する処理も要る。 pg_bigm や pgroonga といった拡張を入れるか、 検索エンジンを別に立てるかという選択も生じる。

一方、数万件という想定規模では、絞り込みだけでもある程度たどり着ける見込みがある。 本当に必要かどうかを、実データが溜まってから判断するほうが、 無駄な作り込みを避けられると考えた。

この判断の弱点

過去の議論を掘り返す場面では、絞り込みが役に立たない。 「あのとき正規化についてどう決めたか」を探すには、 タグが付いていることを期待するしかない。

そしてタグを付けるかどうかは、書いた時点では判断できない。 後で参照されるかどうかがわからないからである。

再検討のきっかけ

  • 1プロジェクトのスレッドが数百件を超えたとき
  • 「前に似た話をした気がするが見つからない」という状況が繰り返されたとき
  • タグの数が増えすぎて、分類としての意味を失いはじめたとき

実装するとしたら

PostgreSQL の中で完結させる案を第一候補とする。 検索エンジンを別に立てると、デプロイ構成にコンテナと運用が増える。

-- pg_bigm による2-gram インデックス（日本語で分かち書きが不要）
CREATE EXTENSION pg_bigm;

ALTER TABLE threads ADD COLUMN search_text text
  GENERATED ALWAYS AS (title || ' ' || body) STORED;

CREATE INDEX threads_search
  ON threads USING gin (search_text gin_bigm_ops);

コメントも対象にするなら、スレッドとコメントを横断する検索が要る。 非公開プロジェクトがあるため、 検索結果に閲覧権限のないものが混ざらないよう、権限の条件を必ず併せる。 検索は権限漏れが起きやすい機能なので、ここは慎重に組む。
