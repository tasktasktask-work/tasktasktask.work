Table

project_members

非公開プロジェクトのメンバー。公開プロジェクトでは参照されない。 プロジェクト管理者の印もここに持つ。

なぜこのテーブルが必要か

非公開プロジェクトを閲覧できる人を列挙するためである。 公開プロジェクトの場合、閲覧できるのは組織メンバー全員なので、このテーブルを見る必要がない。

DDL

CREATE TABLE project_members (
  id         uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid        NOT NULL REFERENCES projects(id),
  user_id    uuid        NOT NULL REFERENCES users(id),
  is_admin   boolean     NOT NULL DEFAULT false,
  deleted_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX project_members_uniq
  ON project_members (project_id, user_id) WHERE deleted_at IS NULL;

CREATE INDEX project_members_by_user
  ON project_members (user_id) WHERE deleted_at IS NULL;

カラム

カラム型説明
is_adminbooleanプロジェクト管理者かどうか。できることはメンバーの追加と削除だけ

役割を boolean にした理由

プロジェクト内の役割は「メンバーを管理できるか」の一点しかない。 スレッドの操作について管理者と一般メンバーの差はない。 取りうる値が二つしかないものに文字列の列挙型を使うと、 将来増えるかのような誤解を招く。

閲覧できるかの判定

-- あるユーザーがあるプロジェクトを閲覧できるか
SELECT EXISTS (
  SELECT 1 FROM projects p
   WHERE p.id = $1
     AND p.deleted_at IS NULL
     AND (
       -- 公開なら組織メンバーであればよい
       (p.visibility = 'public' AND EXISTS (
          SELECT 1 FROM organization_members om
           WHERE om.organization_id = p.organization_id
             AND om.user_id = $2 AND om.deleted_at IS NULL))
       -- 非公開ならプロジェクトメンバーか組織管理者
       OR EXISTS (
          SELECT 1 FROM project_members pm
           WHERE pm.project_id = p.id
             AND pm.user_id = $2 AND pm.deleted_at IS NULL)
       OR EXISTS (
          SELECT 1 FROM organization_members om
           WHERE om.organization_id = p.organization_id
             AND om.user_id = $2 AND om.role = 'admin'
             AND om.deleted_at IS NULL)
     )
);
組織管理者は行を持たなくても管理者として扱う

組織管理者は、project_members に行がなくても すべてのプロジェクトの管理者とみなす。 メンバーが退職者しかいないプロジェクトを引き継げなくなる事態を避けるためである。

つまりプロジェクト管理者かどうかの判定は、 is_admin = true の行があるか、または組織管理者であるか、の論理和になる。
