Table

invitations

組織にメンバーが増える唯一の経路。 メールドメインによる自動参加も、URLを知っていれば入れる仕組みも用意していない。

なぜこのテーブルが必要か

招待は、送った時点ではまだアカウントが存在しないことがある。 そのため organization_members の行を先に作ることはできず、 「誰を、どの組織に、どの役割で呼んだか」を保持する場所が要る。

DDL

CREATE TABLE invitations (
  id                  uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id     uuid        NOT NULL REFERENCES organizations(id),
  email               text        NOT NULL,
  role                text        NOT NULL DEFAULT 'member',
  invited_by_user_id  uuid        NOT NULL REFERENCES users(id),
  token_hash          bytea       NOT NULL,
  expires_at          timestamptz NOT NULL,
  accepted_at         timestamptz,
  accepted_user_id    uuid        REFERENCES users(id),
  revoked_at          timestamptz,
  created_at          timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT invitations_email_lowercase
    CHECK (email = lower(email)),
  CONSTRAINT invitations_role_valid
    CHECK (role IN ('admin', 'member')),
  CONSTRAINT invitations_accepted_consistent
    CHECK ((accepted_at IS NULL) = (accepted_user_id IS NULL))
);

CREATE UNIQUE INDEX invitations_token_hash_key ON invitations (token_hash);

-- 同じ相手への未処理の招待は一件まで
CREATE UNIQUE INDEX invitations_pending_uniq
  ON invitations (organization_id, email)
  WHERE accepted_at IS NULL AND revoked_at IS NULL;

カラム

カラム型説明
emailtext招待先。小文字で正規化して保存する。この時点でアカウントがあるとは限らない
roletext受諾時に organization_members へ渡す役割
token_hashbytea招待URLに含めた値の SHA-256
expires_attimestamptz発行から48時間後
accepted_attimestamptz受諾の時刻
accepted_user_iduuid受諾したアカウント。新規登録の場合はその場で作られたもの
revoked_attimestamptz送った側が取り消した時刻

受諾したときに起きること

  1. そのメールアドレスの users が無ければ作る。パスワードはこの画面で設定する
  2. organization_members に role を引き継いで行を作る
  3. accepted_at と accepted_user_id を埋める
  4. sessions を作ってログイン状態にする

すでに他の組織のアカウントを持っている人の場合、1 は飛ばして 2 から始まる。 同じアカウントが複数の組織に所属する形になる。

すでにアカウントがある人には、パスワードを訊かない

訊いて上書きできると、招待リンクを踏ませるだけで他人のパスワードを書き換えられる。 受諾で変わるのは、所属と、ロックの状態と、ログイン中のアカウントだけである。

表示名も同じ理由で変えない。

一度外れた人を呼び戻したときは、畳んである organization_members の行を起こさず、新しい行を足す。 入って抜けてを繰り返した人には畳んだ行が何本も並んでいて、 まとめて起こすと生きた行が二本になり、部分一意索引に当たる。

受諾は、その画面を開いた時点では起きない。 リンクを先読みするメールソフトに、勝手に消費させないためである。

有効期間48時間の帰結

招待は「まだこのサービスを知らない人」に届く。 マジックリンクのように受け手が待っている状況ではない。 会議中や休暇中に届いた招待は期限切れになりやすく、再送の依頼が発生する。

マジックリンクと期間を揃えるという判断でこの値になった。 運用してみて再送が頻発するようなら、招待だけ長くすることを検討する。
