Table

magic_link_tokens

メールで送るログイン用のURLに埋め込むトークン。48時間で切れ、一度使うと無効になる。 このテーブルはアカウントロックの解除経路も兼ねている。

なぜこのテーブルが必要か

マジックリンクは、メールを受け取れることを本人性の証明として使う。 そのために、発行した値と発行先を突き合わせる記録が要る。

このテーブルがあることで、パスワード再設定の仕組みを別に作らずに済む。 忘れた人はマジックリンクで入って設定し直せばよい。

DDL

CREATE TABLE magic_link_tokens (
  id          uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid        NOT NULL REFERENCES users(id),
  token_hash  bytea       NOT NULL,
  expires_at  timestamptz NOT NULL,
  used_at     timestamptz,
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX magic_link_tokens_hash_key ON magic_link_tokens (token_hash);
CREATE INDEX magic_link_tokens_by_user
  ON magic_link_tokens (user_id) WHERE used_at IS NULL;

カラム

カラム型説明
token_hashbyteaURLに含めた値の SHA-256。生の値は保存しない
expires_attimestamptz発行から48時間後
used_attimestamptz使用した時刻。埋まっていれば再利用できない

使用時に行うこと

トークンの検証に成功したとき、同じトランザクションで次を行う。

  1. used_at を埋める
  2. sessions に行を作る
  3. users.locked_at と users.failed_login_count をリセットする

3 がロックの自動解除にあたる。 パスワードを何度間違えていても、メールを受け取れる本人であれば自力で復帰できる。

有効期間48時間の位置づけ

ログイン用のリンクとしては長い部類に入る。 招待と期間を揃えたいという判断による。 メールボックスが漏れている状況では、48時間のあいだ第三者がログインできる。 短縮する場合は、招待側と一緒に見直すことになる。
