Table

sessions

ログイン中であることを表す。30日で切れ、アクセスによる延長はしない。 Cookie に入る値そのものは保存しない。

なぜこのテーブルが必要か

ログイン状態をサーバー側で持つことで、失効させられるようにするためである。 署名付きトークンだけで済ませると、盗まれたセッションを個別に無効化できない。

DDL

CREATE TABLE sessions (
  id          uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid        NOT NULL REFERENCES users(id),
  token_hash  bytea       NOT NULL,
  expires_at  timestamptz NOT NULL,
  revoked_at  timestamptz,
  user_agent  text,
  created_ip  inet,
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX sessions_token_hash_key ON sessions (token_hash);
CREATE INDEX sessions_by_user ON sessions (user_id) WHERE revoked_at IS NULL;

カラム

カラム型説明
token_hashbyteaCookie に入れた値の SHA-256。生の値は保存しない
expires_attimestamptz作成から30日後。延長しない
revoked_attimestamptzログアウトや強制失効の時刻
user_agenttext「他の端末からログアウト」の画面で端末を見分けるため
created_ipinet同上。偽装されうる値である

生の値を保存しない

データベースの中身が漏れたとき、保存されているのがハッシュであれば、 そこからセッションを乗っ取ることはできない。 Cookie の値は HttpOnly かつ Secure かつ SameSite=Lax で送る。

延長しない

アクセスのたびに有効期限を伸ばす方式を取らない。 毎回の書き込みが発生することと、「30日使えば必ず再ログインになる」という予測しやすさを優先した。

deleted_at を持たない

このテーブルは論理削除の対象外である。 失効は revoked_at で表し、期限切れの行は定期的に物理削除してよい。 記録として残す価値がなく、放置すると増え続けるためである。
