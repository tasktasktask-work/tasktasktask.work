Database

データベース全体構成

15 のテーブルがある。 ORM を使わず SQL を直接書く構成なので、スキーマがそのまま設計書として読める状態を保つ。 ここではテーブル間の関係だけを扱う。個々のカラムは各テーブルのページにある。

三つの原則

すべてのデータは組織に属する

マルチテナントであるため、クエリの条件から組織が落ちると他社のデータが混ざる。 これは最も起きてはならない事故である。

そこで、親を辿れば組織にたどり着けるテーブルにも organization_id を直接持たせる。 comments から組織を知るのに threads と projects を経由させない。 正規化としては冗長だが、権限判定を単純な等値条件で書けることを優先した。

物理削除をしない

どのテーブルにも deleted_at を置き、行を消さない。 スレッド番号を欠番のまま保ち、外部に貼られたURLへ「削除済み」と応答できるようにするためである。

この原則から外した二つのテーブル

thread_tags と watches は中間テーブルであり、付けたり外したりが日常的に起きる。 ここに deleted_at を置くと、外して付け直すたびに行が積み上がり、一意制約も条件付きにせざるを得なくなる。 この二つだけ物理削除とした。方針からの意図的な逸脱であり、レビューで例外として承認されている。 付け外しの記録が必要になった場合は、deleted_at ではなく監査ログで扱う。

日付と時刻を使い分ける

課題の期間は date 型で持つ。時刻を持たない。 組織ごとにタイムゾーンを設定できるため、時刻を持つと設定変更で既存の日付が前後する。

一方、コメントの投稿時刻のような記録は timestamptz で持つ。 この型はタイムゾーンを保存せず、UTC における時刻の一点だけを持つ。 表示のための変換は、セッションの設定に頼らず組織のタイムゾーンを引数で渡して行う。 扱いの詳細を規約に定めた。

updated_at はトリガで埋める

updated_at を持つテーブルには、共通のトリガを仕掛ける。 アプリケーション側で毎回 updated_at = now() を書く方式は、書き忘れが起きる。

CREATE OR REPLACE FUNCTION set_updated_at() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END;
$$;

書き忘れが見つけにくいのは、スレッド一覧の既定の並び順が 更新の新しい順だからである。 更新したのに一覧で下に沈む、という形でしか表面化しない。

なお comments は updated_at を持たないため、 トリガも仕掛けない。投稿後に更新される経路が存在しない。

この関数は Atlas の管理下にない

Atlas は無料の範囲では関数とプロシージャを扱えない。 schema/ に置くと migrate diff がエラーになる。

そのため関数とトリガは db/functions.sql に分け、 マイグレーションの適用後に流している。 詳しくはスキーマ移行に書いた。

採番のしくみ

スレッド番号は組織の中で通し番号になる。 プロジェクトごとに1から振らないため、シーケンスを組織ごとに用意することになるが、 Postgres のシーケンスは動的に作りにくい。

そこで organizations.next_thread_number を持ち、スレッド作成時に行ロックを取って加算する。

BEGIN;
  UPDATE organizations
     SET next_thread_number = next_thread_number + 1
   WHERE id = $1
  RETURNING next_thread_number - 1 AS number;
  INSERT INTO threads (organization_id, project_id, number, ...)
  VALUES ($1, $2, $number, ...);
COMMIT;

同じ組織で同時にスレッドを作ると、片方が待つ。 100人規模ならこの待ちは問題にならない。 番号が飛ばないことよりも、重複しないことを優先した設計である。

ロールバックすると番号が飛ぶ

トランザクションが失敗すると加算も巻き戻るので、この方式では番号は飛ばない。 ただし、そのぶん同時実行性は下がる。 シーケンスを使えば速いが、失敗のたびに欠番が出る。 番号が飛ぶ理由が「別プロジェクトが使った」だけであるほうが説明しやすいため、この方式を選んだ。
