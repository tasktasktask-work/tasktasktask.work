Table

organizations

テナントの境界。すべてのデータがこの下に入る。 加えて、スレッド番号の採番元でもある。

なぜこのテーブルが必要か

マルチテナントの構成では、どのデータがどの顧客のものかを示す起点が要る。 組織がそれにあたる。

もう一つの役割が採番である。スレッド番号を組織の中で通し番号にすると決めたため、 「次に使う番号」をどこかに置く必要がある。組織ごとにシーケンスを作るのは扱いにくいので、この行に持たせた。

DDL

CREATE TABLE organizations (
  id                  uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  name                text        NOT NULL,
  slug                text        NOT NULL,
  language            text        NOT NULL DEFAULT 'ja',
  timezone            text        NOT NULL DEFAULT 'Asia/Tokyo',
  next_thread_number  integer     NOT NULL DEFAULT 1,
  deleted_at          timestamptz,
  created_at          timestamptz NOT NULL DEFAULT now(),
  updated_at          timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT organizations_name_not_blank
    CHECK (btrim(name) <> ''),
  CONSTRAINT organizations_slug_format
    CHECK (slug ~ '^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$'),
  CONSTRAINT organizations_language_supported
    CHECK (language IN ('ja')),
  CONSTRAINT organizations_next_number_positive
    CHECK (next_thread_number >= 1)
);

CREATE UNIQUE INDEX organizations_slug_key
  ON organizations (slug) WHERE deleted_at IS NULL;

カラム

カラム型説明
iduuid主キー
nametext画面に出る組織名。変更できる
slugtextURL に含まれる識別子。/o/{slug}/... の形で使う
languagetext表示言語。初期リリースでは ja のみ許可する
timezonetext日時表示に使う。IANA のタイムゾーン名
next_thread_numberinteger次に払い出すスレッド番号。行ロックを取って加算する
deleted_attimestamptz論理削除の時刻
拡張を使わない

大文字小文字を区別しない識別子なので citext が候補になる。 採らなかった理由は二つある。

ひとつは、CHECK 制約の正規表現が小文字と数字しか許さないこと。 小文字しか格納できないなら、比較を大文字小文字非依存にする意味がない。

もうひとつは、Atlas が無料の範囲では CREATE EXTENSION を扱えないことである。 メールアドレス（users、invitations）も 同じ理由で text にし、小文字に揃えて保存する。 このプロジェクトは拡張をひとつも使わない。

language に CHECK を置いた理由

選べる値がひとつしかないのに列を持つのは、後から列を足すほうが高くつくからである。 ただし列だけあって値の検証がないと、実装が対応していない値が入りうる。 対応言語を増やすときに CHECK も一緒に更新する、という手順を強制するために制約を置いた。

関係

organizations ──┬─< organization_members >── users
                ├─< projects
                ├─< tags
                ├─< invitations
                ├─< threads        （project 経由でも辿れるが直接も持つ）
                ├─< comments
                ├─< attachments
                └─< notifications

スレッドやコメントは projects を辿れば組織にたどり着ける。 それでも organization_id を直接持たせているのは、権限判定を結合なしの等値条件で書けるようにするためである。
