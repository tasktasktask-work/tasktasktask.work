Table

users

アカウント。組織には属さない。 ひとりが複数の組織に所属するため、所属関係は別のテーブルが持つ。

なぜこのテーブルが必要か

ログインする主体を表す。 メールアドレスはシステム全体で一意にする。 同じ人が二つの組織に招待されたとき、二つのアカウントができてしまうと、 片方でしかログインできない状態が生まれるためである。

DDL

CREATE TABLE users (
  id                          uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  email                       text        NOT NULL,
  display_name                text        NOT NULL,
  password_hash               text,
  failed_login_count          smallint    NOT NULL DEFAULT 0,
  locked_at                   timestamptz,
  email_notifications_enabled boolean     NOT NULL DEFAULT true,
  deleted_at                  timestamptz,
  created_at                  timestamptz NOT NULL DEFAULT now(),
  updated_at                  timestamptz NOT NULL DEFAULT now(),

  -- 大文字小文字を区別しない比較は、値を小文字に揃えることで不要にする
  CONSTRAINT users_email_lowercase
    CHECK (email = lower(email)),
  CONSTRAINT users_email_shape
    CHECK (email ~ '^[^@[:space:]]+@[^@[:space:]]+\.[^@[:space:]]+$'),
  CONSTRAINT users_display_name_not_blank
    CHECK (btrim(display_name) <> ''),
  CONSTRAINT users_failed_login_count_range
    CHECK (failed_login_count BETWEEN 0 AND 10)
);

CREATE UNIQUE INDEX users_email_key
  ON users (email) WHERE deleted_at IS NULL;

カラム

カラム型説明
emailtextログインに使う。小文字で正規化して保存する
display_nametext画面に出る名前。必須。一文字目がハンコアバターになる
password_hashtextArgon2id のハッシュ。NULL を許す
failed_login_countsmallintパスワード入力の連続失敗回数。成功で0に戻る
locked_attimestamptzアカウントロックの時刻。NULL ならロックされていない
email_notifications_enabledboolean通知メールを受け取るか。/me で切り替える

citext ではなく text にした理由

大文字小文字を区別しない比較のために citext 拡張を使う案もあった。 採らなかったのは、Atlas がスキーマの正本を読むとき、 無料の範囲では CREATE EXTENSION を扱えないためである。

拡張をひとつ増やす代わりに、値を小文字に揃えて保存する。 書き込む側が lower() を忘れたら users_email_lowercase で落ちるので、 揃っていない値が入り込むことはない。 スキーマ移行に経緯を書いた。

password_hash が NULL を許す理由

マジックリンクだけを使う人が存在しうるためである。 招待からの登録ではパスワードを設定するが、将来パスワードを廃止する人が出ても列を残したまま扱える。

アカウントロックの表現

ロックは locked_at が NULL でないことで表す。時間経過では解除しない。

解除の経路は二つある。

  • マジックリンクでのログイン成功時に locked_at と failed_login_count をリセットする
  • 組織管理者による手動解除

ロックがかかった時点で本人へメールを送る。 この通知がないと、第三者に締め出された人は理由も解除方法もわからないまま止まる。

ここに置かない情報

失敗した試行の履歴（いつ、どのIPから）は持たない。 監査ログを導入するときにまとめて扱う。 そのため現状では、ロックの原因を後から調べる手段がない。
