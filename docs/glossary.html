Glossary

用語集

このプロダクトは既存の課題管理ツールを下敷きにしていない。 そのため「課題」や「状態」といったありふれた言葉であっても、他所での意味をそのまま持ち込むと食い違う。 ここに並ぶのは、開発者と現場が同じ絵を思い浮かべるために必要な最小限の語である。

運用の決まり

会話の中で新しい語が出てきたら、設計や実装よりも先にここへ書く。 そして、その語を使っている本文の側からもこのページへリンクを張る。 どこからも参照されていない語が残っていたら、それは使われていない語か、リンクの張り忘れである。

組織とプロジェクト

組織organization

ひとつの会社やチームに対応する、データの一番外側の器を組織と呼ぶ。 ユーザー、プロジェクト、スレッド、タグ。すべてがいずれかの組織に属し、組織をまたいで参照されることはない。

ひとりのユーザーが複数の組織に所属できる。 業務委託で二社に関わる人や、事業部をまたぐ人が実際にいるためである。 そのため画面のURLには常に組織を示す文字列が含まれ、いま自分がどの組織を見ているかが分かるようになっている。

PM業務委託の人にも入ってもらいたいんですが、うちの組織に招待すると全部見えちゃいますか。

開発者組織に招待すると、公開プロジェクトは全部見えます。見せたくないものは非公開プロジェクトにしてください。

関連する機能組織とメンバー

組織管理者organization admin

組織の設定変更、メンバーの招待、プロジェクトの作成、そして論理削除を行える役割を組織管理者と呼ぶ。 それ以外のメンバーは組織メンバーと呼び、役割はこの二段しかない。

組織管理者は複数人置ける。 ひとりに限ると、その人が退職したりアカウントを失ったときに、組織そのものが操作不能になるからである。

組織管理者は、自分が参加していない非公開プロジェクトも閲覧でき、そのプロジェクト管理者としても扱われる。 退職者しかメンバーがいないプロジェクトを引き継げなくなる事態を避けるためである。

PMプロジェクトを作れるのは誰ですか。

開発者組織管理者だけです。メンバーが自由に作れるようにはしていません。

組織のスコープorganization scope

「いまどの組織を、誰として見ているか」をひとまとめにした値を組織のスコープと呼ぶ。 組織の id、利用者の id、組織管理者かどうか、表示に使うタイムゾーンの四つを持つ。

組織はデータの境界なので、問い合わせの条件から組織が落ちれば他社のデータが混ざる。 そこでデータにさわる関数はすべて、この値を第一引数に取る。 URL の /o/{slug}/ から所属を確かめて組み立てるので、 所属していなければスコープが作れず、その先の問い合わせも書けない。

ただし、スコープに入っている「組織管理者かどうか」は画面の出し分けにしか使わない。 書き込みの可否は、そのつど SQL の中で確かめる。 呼ぶ側は好きな値のスコープを組み立てられるからである。

PM業務委託の方が二社に入っていますが、片方のデータがもう片方に出たりしませんか。

開発者URL の組織から毎回スコープを組み直すので、混ざりません。組織を外れれば、その場で何も引けなくなります。

プロジェクトproject

スレッドを入れる箱をプロジェクトと呼ぶ。 すべてのスレッドはいずれかのプロジェクトに属し、後から別のプロジェクトへ移すことはできない。

プロジェクトはただの分類ではない。 ガントチャートが一枚に描く範囲、メンションの候補に出る人の範囲、そして閲覧できる人の範囲。 これらすべての境界がプロジェクトである。

持っている情報は、名前とプロジェクトキーと説明文、それにアーカイブされているかどうかだけである。 期間は持たない。プロジェクトの期間を知りたければ、中の課題を見ればわかる。

PMこの案件、途中でプロジェクトを分けたくなったらどうすれば。

開発者移動はできません。新しいプロジェクトを作って、そちらでスレッドを立て直してもらう形になります。

PMけっこう痛いですね。最初の切り方を慎重にします。

プロジェクトキーproject key

プロジェクトごとに付ける短い記号をプロジェクトキーと呼ぶ。 半角の英大文字と数字で2文字から10文字、組織の中で重複しない。

キーはスレッド識別子の前半に現れる。 WEB-128 の WEB がそれである。 後から変更することはできない。すでに配られた識別子の見た目が変わり、口頭や議事録での参照が通じなくなるためである。

PMキーを WEB から FRONT に変えたいんですが。

開発者変更できない仕様です。番号だけは組織で通しているので取り違えは起きませんが、表示は WEB のままになります。

公開プロジェクトと非公開プロジェクトpublic / private project

組織のメンバー全員が閲覧できるプロジェクトを公開プロジェクト、指定したメンバーだけが閲覧できるものを非公開プロジェクトと呼ぶ。 この設定は後から切り替えられる。

非公開から公開へ切り替えると、それまで限られた人しか見られなかったスレッドが組織全員に見えるようになる。 取り消しはできても、見られた事実は取り消せない。 そのため切り替えの操作には確認をはさむ。

PM人事の検討を進めるプロジェクトを作りたいんですが、他の人には見せたくなくて。

開発者非公開にしてください。メンバーに入れた人と組織管理者しか見えません。メンションの候補にも、その人たちしか出ません。

プロジェクトを作った組織管理者が自動的に管理者になる。 加えて、すべての組織管理者が全プロジェクトの管理者として扱われる。

スレッド

スレッドthread

このプロダクトが扱う情報の基本単位をスレッドと呼ぶ。 タイトルと本文があり、その下にコメントが時系列で一本に連なる。

他の課題管理ツールとの違いはここにある。 普通のツールは「課題」を基本単位に置き、議論はその付属物として扱う。 このプロダクトでは逆で、基本単位はスレッドであり、課題はその種別のひとつでしかない。

この設計は、実装のゴールが決まっていない話をどこに書けばいいのか、という問題への答えである。 ゴールが定まる前の相談も、答えが返ってくれば済む疑問も、課題と同じ場所に同じ形で置ける。

PMまだ課題として書けるほど固まってない相談があるんですが、どこに書けばいいですか。

開発者種別を議論にしてスレッドを立ててください。課題と同じ場所に並びます。

PMそこで話がまとまったら、そのスレッドが課題になるんですか。

開発者いえ、変換はできません。課題のスレッドを別に立てて、議論のスレッドを親にしてください。

種別thread type

スレッドがどういう性質の話かを示す区分を種別と呼ぶ。 課題、議論、質問の三つで固定されており、組織ごとに増やすことはできない。

種別によって使える機能が変わる。

種別進捗率期間親子ガント
課題0から100の任意の値持つ可載る
議論0か100のみ持たない可載らない
質問0か100のみ持たない可載らない

種別は後から変更できない。 議論として立てたスレッドを課題に作り変えることはできず、課題のスレッドを新たに立て直すことになる。

やるべきことが決まっていて、終わりの形が言えるスレッドを課題と呼ぶ。 三つの種別のうち、これだけが期間を持ち、ガントチャートに載る。

進捗率は0から100の任意の値を取れる。 ここが他の二つの種別との違いで、「半分終わった」という状態を表せるのは課題だけである。

議論discussion

何をするか決まっていない相談を置くスレッドを議論と呼ぶ。 実装のゴールが存在しないため、期間を持たずガントにも載らない。

状態はオープンかクローズの二つだけである。 話がついたらクローズする。そこから生まれた作業は、課題のスレッドを別に立てて、この議論を親にする。

PMこの議論、結論は出たんですけど、まだやることが決まってなくて。

開発者結論が出たならクローズしていいです。やることが決まったら、あとから子に課題をぶら下げてください。

質問question

答えが返ってくれば済む疑問を置くスレッドを質問と呼ぶ。 議論と同じく期間を持たず、状態はオープンかクローズの二つだけである。

議論との違いは、決めることがあるかどうかにある。 答えを知っている人がいれば終わるものが質問で、関係者で決めなければ終わらないものが議論である。

スレッドに割り当てられる連番をスレッド番号と呼ぶ。 組織の中で通し番号になっており、プロジェクトごとには振り直さない。

そのため、ひとつのプロジェクトだけを見ると番号が飛ぶ。 WEB-3 の次が WEB-7 になることは正常である。 間の番号は同じ組織の別プロジェクトが使っている。

開発者番号は組織で通しているので、他のプロジェクトが使っています。消えたわけではありません。

番号だけでも一意に定まるが、キーを前に置くことでどのプロジェクトの話かがその場でわかる。 会議で口に出すときも、議事録に書くときも、この形で参照する。

親子関係parent / child

スレッドの下に別のスレッドをぶら下げる関係を親子関係と呼ぶ。 上を親スレッド、下を子スレッドと呼ぶ。

階層の深さに制限はない。 そして種別をまたいでよい。 議論の子に課題を置くことも、課題の子に質問を置くこともできる。 ただしプロジェクトはまたげない。親と子は必ず同じプロジェクトに属する。

親子関係には、集計の意味を持たせていない。 親の進捗率は子から計算されず、親の期間も子とは独立して入力する。 親が持つ期間は、その塊全体としていつまでに終わらせたいかを表す。 子がそこからはみ出したときははみ出し警告で知らせるが、値を書き換えることはしない。

PM子課題を全部100%にしたら、親も自動で100%になりますか。

開発者なりません。親の進捗率は自分で入れてください。子が終わっていても、親としてやり残しがあることはあるので。

進捗と期間

進捗率progress

スレッドがどこまで進んだかを0から100の整数で表したものを進捗率と呼ぶ。 このプロダクトには、これとは別の状態欄が存在しない。

値課題での意味議論と質問での意味
0未着手オープン
1から99進行中取らない
100完了クローズ

値は担当者が自分で入力する。1刻みで自由に入れられるが、入力欄には0、25、50、75、100の候補を出して選びやすくする。

この設計で表せないこと

進捗率だけを持つ設計では、「やらないと決めた課題」と「まだ手をつけていない課題」がどちらも0のままになり、区別できない。 同じ理由で「レビュー中」のような工程も表せない。 どう扱うかは各組織の運用に委ねる方針を取った。却下の表現に経緯を記録している。

期間period

課題が持つ開始日と終了日の組を期間と呼ぶ。 時刻は持たず、日付だけを扱う。

時刻を持たせない理由は、組織ごとにタイムゾーンを設定できるようにしたためである。 時刻を持つと、設定を変えた瞬間に既存の日付が前後する。 日付だけなら、その事故が構造的に起きない。

コメントcomment

スレッドにぶら下がる発言をコメントと呼ぶ。 投稿順に一本の列として並び、スレッドの中で枝分かれすることはない。

一度投稿したコメントは編集も削除もできない。 コメントは「その時点で誰が何と言ったか」の記録であり、後から書き換えられると、それを前提に進んだ議論の意味が失われるためである。

この扱いはスレッドの本文とは異なる。 本文は現在の課題の定義を表すものなので、調査が進めば書き換わってよい。 書き換えたことは「編集済み」の印で示すが、以前の内容は残さない。

PMコメントの誤字を直したいんですが。

開発者直せません。訂正のコメントを続けて書いてもらう形になります。

PM不便ですけど、言った言わないが起きないのは助かりますね。

メンションmention

コメントや本文の中で @ に続けて人を指名する書き方をメンションと呼ぶ。 指名された人には通知が飛ぶ。

候補に出るのは、そのプロジェクトを閲覧できる人だけである。 非公開プロジェクトのメンバーでない人を指名できてしまうと、閲覧権限のないスレッドの内容を含む通知が届く。 それは非公開という設定の意味を失わせる。

ウォッチが自動では付かない仕様のため、メンションは相手に気づいてもらうための主要な手段になる。 誰かに宛てて書くときは、その人を指名する運用が前提になる。

分類と通知

タグtag

スレッドに付ける色つきの目印をタグと呼ぶ。 ひとつのスレッドに何個でも付けられる。

タグは組織の単位で定義し、プロジェクトをまたいで共通に使う。 誰でも新しいタグを作れる。

タグが必要なのは、親子関係が階層という一本の軸しか表せないからである。 bug や 要相談 のように階層と直交する分類は、親子では代わりにならない。

関連する用語スレッド親子関係組織
関連する機能タグ

ウォッチwatch

そのスレッドに新しいコメントが付いたら知らせてほしい、という意思表示をウォッチと呼ぶ。 自分でボタンを押して付け、押して外す。

自動では付かない。 スレッドを立てても、担当者になっても、コメントを書いても、ウォッチしたことにはならない。

運用上の前提

自動で付かないため、自分が立てたスレッドに返信が来ても、ウォッチしていなければ気づけない。 返信するときは相手をメンションで指名する、という運用がこの設計の前提になっている。 自動付与を入れるかどうかは通知の拡張に記録した。

関連する機能通知とウォッチ

通知notification

自分に関係する出来事を知らせる仕組みを通知と呼ぶ。 アプリの中の一覧とメールの両方に、同じ内容が届く。

通知が飛ぶのは次の三つの場合である。

  • メンションで指名されたとき
  • 担当者に設定されたとき
  • ウォッチしているスレッドに新しいコメントが付いたとき

アプリ内の通知には既読と未読がある。 メールは送りっぱなしなので、何を見落としたかを確かめる場所としてアプリ内の一覧が要る。

メール通知はユーザーごとにまとめて止められる。 止める手段がないと、煩わしく感じた人に迷惑メールとして報告され、送信ドメインの評価が下がる。 そうなるとマジックリンクまで届かなくなり、ログインそのものができなくなる。

保管と片付け

添付ファイルattachment

スレッドやコメントに付けるファイルを添付ファイルと呼ぶ。 サーバー上のローカルボリュームに保存する。

拡張子による制限は設けていない。 ログでも設定ファイルでも圧縮ファイルでも、そのまま添付できる。 制限があるのは大きさだけで、1ファイル10MBまでとする。

種別を検査しない代わりに、配信の仕方で守る。 すべてのファイルを、必ずダウンロードとして返す。 ブラウザが中身を見て勝手に解釈することもなく、 レスポンスにはスクリプトの実行を禁じる指示も添える。 画面に表示する画像だけは、サーバー側で読み直して書き出し直す。 読めなかったものは画像として扱わず、ダウンロードできるだけのファイルになる。

PM実行ファイルは弾いてくれるんですよね。

開発者弾きません。拡張子を変えたり圧縮したりすれば通ってしまうので、弾いているつもりになるほうが危ないと考えました。中身を検査するならウイルススキャンを入れる必要があります。

アーカイブarchive

終わったものを視界から外す操作をアーカイブと呼ぶ。 スレッドにもプロジェクトにも行える。

アーカイブしたスレッドは読み取り専用になる。 新しいコメントも、子スレッドの追加もできない。 一覧やガントには既定で出ないが、絞り込みを切り替えれば表示できる。

親をアーカイブしても子は連鎖しない。 親が畳まれても、子にはまだ動いているものがありうるからである。 そのため、活動中の子を持つアーカイブ済みスレッドは、一覧に読み取り専用として出しておく。 子だけが宙に浮いて見えなくなる状態を避けるためである。

プロジェクトをアーカイブすると、配下のスレッドがまとめて読み取り専用になる。 こちらは個々のスレッドのアーカイブ状態を書き換えず、プロジェクト単位で凍結する。

論理削除soft delete

レコードを残したまま、削除された印だけを立てる方式を論理削除と呼ぶ。 このプロダクトでは、どのテーブルについても物理削除を行わない。

削除に至る道筋は決まっている。 まずアーカイブし、そのうえで論理削除する。 いきなり削除することはできない。

操作できるのは組織管理者だけで、いつでも復元できる。 レコードが残るためスレッド番号も欠番のまま保たれ、外部に貼られたURLは「削除済み」と分かる形で応答できる。

入り口

マジックリンクmagic link

メールで届くURLを開くだけでログインできる仕組みをマジックリンクと呼ぶ。 有効期間は48時間で、一度使うと無効になる。

パスワードによるログインも併用する。 同じアカウントがどちらの方法でも入れるため、パスワードを忘れた人はマジックリンクで入って設定し直せる。 パスワード再設定の仕組みを別に作る必要がない。

この併用はアカウントロックの解除手段にもなっている。

招待invitation

組織に人を加える唯一の手段を招待と呼ぶ。 組織管理者がメールアドレスを指定して送る。

受け取った人は、リンクからパスワードを設定してアカウントを作る。 リンクの有効期間はマジックリンクと揃えて48時間とする。

メールドメインによる自動参加や、URLを知っていれば誰でも入れる仕組みは用意しない。

関連する用語組織組織管理者マジックリンク
関連する機能認証／組織とメンバー

アカウントロックaccount lock

パスワードの入力に連続して失敗したとき、そのアカウントでのパスワードログインを止めることをアカウントロックと呼ぶ。 10回連続で失敗するとロックがかかり、時間経過では解除されない。

解除はマジックリンクでのログインに成功した時点で自動的に行われる。 メールを受け取れることが本人である証拠になっており、管理者の手を借りずに復帰できる。

この仕組みが必要な理由

時間で自動解除しない設計は、そのままだと第三者による締め出しの道具になる。 他人のメールアドレスに対してでたらめなパスワードを10回送れば、その人をサービスから閉め出せてしまう。 マジックリンクによる自力解除と、ロックされた事実を本人へメールで知らせる仕組みが、これへの答えである。

見せ方

ガントチャートgantt chart

課題の期間を横方向の時間軸に並べた図をガントチャートと呼ぶ。 描く範囲はプロジェクトひとつぶんで、横軸の刻みは日である。

左側に並ぶ行は親子関係のとおりに入れ子で表示し、折りたためる。 スレッド一覧が階層を持たないのと対照的だが、これは目的の違いによる。 一覧は探すための画面であり、ガントは計画の構造を読むための画面である。 親と子の期間の関係は、入れ子で並んでいなければ読み取れない。

進捗率が100の課題も薄く表示する。 アーカイブ済みのものは表示しない。 期間未設定の課題は図の下に別枠で並べる。

バーをドラッグして期間を変えることはできない。 期間の変更はスレッドの詳細画面から行う。
