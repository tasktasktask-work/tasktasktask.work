DevOps 08

ブラウザで押して確かめる

ここにあるのは、ブラウザの中でしか起きないことだけである。 判定の網は pnpm test が持っている。両方を同じ場所で見ない。

なぜ要ったか

2026-09-08 に本番へ初めて反映した日、四つの不具合が出た。 そのうち二つは、手元でどれだけ確かめても現れなかった。

不具合捕まえるのに要ったもの
マジックリンクの着地が 0.0.0.0 へ飛ぶcurl でヘッダを見れば足りた
CSS が画面に届かないclass の照合で足りた（pnpm check に入れた）
blob は中身が空です でコメントを投稿できないブラウザが要った
保存すると入力欄が元の値へ戻るブラウザが要った

下の二つは、どちらもブラウザの中で起きる。 ファイル欄の符号化も、フォームの reset() も、 リクエストを手で組む試験では通らない層にある。

この二つが往復の原因になった

どちらも一度は直したつもりで本番へ出し、直っていなかった。 確かめる手段が無いまま「たぶんこうだろう」で直したためである。

入れたあと、四つの不具合をすべて元に戻して走らせた。 四つとも落ちた。この試験があれば、往復は起きなかった。

走らせ方

pnpm build   # standalone の出力が要る
pnpm e2e

ビルドしていなければ、その旨を出して止まる。 データベースは pnpm test と同じものを使う。

入口見るものかかる時間
pnpm check型、整形、共有スタイル、定義の無い class、移行の規約数秒
pnpm test判定、SQL、制約。483件数秒
pnpm e2eブラウザの中でしか起きないこと。9件25秒ほど

何を置くか

置くのは、ブラウザが要るものだけである。 権限の判定も、SQL の条件も、ここでは見ない。 全画面を押して回る形にすると、遅くて壊れやすく、落ちても誰も直さなくなる。

ファイル見ているもの
login.spec.tsマジックリンクの着地、二度使えないこと、カードに意匠が効いていること
styles.spec.tsログイン画面に CSS と書体が届いていること
comment.spec.ts添付なしで投稿できること、添付ありで名前が保たれること
thread-props.spec.ts保存後に欄が戻らないこと、知らせの出し引き

下ごしらえと後片付け

組織と最初の管理者は画面から作れないので、データベースへ直に入れる。 tests/e2e/fixtures.ts の sow がそれを行い、 終わったら reap が消す。

印は走らせるたびに変える。途中で落ちても、次の回の種に当たらない。

ログインはマジックリンクを通す。 トークンを直に入れてから /auth/magic?token=... を開く。 画面のログイン欄を使わないのは、メールが届くのを待つことになるためである。

接続先を差し替える

E2E_BASE_URL=https://tasktasktask.work pnpm e2e

与えると、自分でサーバーを起こさない。 データベースにも手が届かないので、種を蒔く試験は外れる （test.skip(!canSeed, ...)）。残るのは styles.spec.ts だけである。

本番で何を確かめるかは、まだ決めていない。 専用の組織を置いて書き込みまで見るのか、読むだけに留めるのか。 向けるときに決める。継ぎ目だけを先に作ってある。

落ちたときに残るもの

トレースとスクリーンショットが test-results/ に残る。 通ったときは何も残らない。置き場は .gitignore に入れてある。

pnpm exec playwright show-trace test-results/<試験の名前>/trace.zip

トレースには押した順と、各段階の DOM がそのまま入っている。 読むための道具なので、ここが効く。

ブラウザの実体

chromium は約170MB ある。 .devcontainer/Dockerfile に入れてあるので、 次に開発コンテナを作り直したときから何もしなくても使える。

版は package.json の @playwright/test と揃える。 ずれると playwright が「入っていない」と言って落ちる。

アーキテクチャ

開発コンテナは arm64 で、GitHub の runner は x86_64 である。 playwright install はどちらでも合うものを取ってくるので、 そのままで動く。イメージの側とは別の話である （デプロイにある注意はそちら）。

CI には入れていない

Test ワークフローで走るのは pnpm check と pnpm test と pnpm build までである。

入れていないのは、まず手元で確かめるための道具として作ったためである。 CI で走らせるなら、runner にブラウザを落とす時間が毎回かかる （キャッシュを効かせるにしても、置き場と鍵を決めることになる）。 必要になったときに決める。
