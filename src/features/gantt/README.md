# ガントチャート

プロジェクト一枚ぶん。日単位。階層表示。読み取り専用。
期間未設定の課題を隠さないことが、この画面の要である。

仕様は [docs/features/gantt/index.html](../../../docs/features/gantt/index.html) にある。
先にそちらを読むこと。決めた理由まで書いてある。

## ここに置くもの

| ファイル | 役目 |
| --- | --- |
| `layout.ts` | 行を選び、木に組み直し、並べ、切り、範囲を決める。判定を持たない |
| `queries.ts` | 種になる課題を選び、祖先まで引き上げる。別枠と件数もここ |
| `GanttChart.tsx` | 描画。折りたたみと、開いた直後のスクロールだけを持つ |
| `path.ts` | 行き先の組み立て |

## 図に出る行

**期間を持つ課題と、その祖先。** これがすべてである。

祖先は、期間が入っていなくても、アーカイブ済みであっても残す。
落とすと子のインデントの根拠が消え、その子が根の無い行として浮く。

子を持たない期間未設定の課題は図に出ない。下の別枠が拾う。
したがって、期間の無い親は図と別枠の両方に現れる。これは重複ではない。
図の行は「子がここにぶら下がっている」ことを、別枠の行は「まだ計画に載っていない」ことを言っている。

## `layout.ts` を分けてある理由

この画面の判断のほとんどは「どの行を出すか」に集まっている。
問い合わせと描画に混ぜると、切ったときの祖先の扱いも、はみ出しの判定も、
画面を開かないと確かめられない。

実際、この分け方が「親が輪になっていると図が丸ごと空になる」不具合を見つけた。

## 決まりごと

- データにさわる関数は、組織のスコープ（`OrgScope`）を第一引数に取る
- 閲覧できるプロジェクトの判定は `#lib/db.ts` の `VISIBLE_PROJECT_IDS` を使う。ここに書き写さない
- import には必ず拡張子を書く（[規約](../../../docs/devops/coding-conventions/index.html#imports)）
- 「畳む」はアーカイブを指す。行を閉じるほうは「折りたたみ」と呼ぶ

## 二重になっている守り

次の二つは、データベースの制約と重なっていて、外してもテストが落ちない。
落とせないと分かったうえで残してある。

- `period()` が終了日も見ていること … `threads_period_paired` が組を保証する
- 取得の条件の `type = 'kadai'` … `threads_period_only_for_kadai` により、期間で絞れば議論と質問は落ちる

制約そのものは `tests/schema.test.ts` が確かめている。
