# billing

組織ごとに、人数ぶんの月額を後払いで受け取る。
払われていない組織は書き込みだけが止まり、読み取りは全部残る。

仕様は `docs/features/billing/index.html`。

## 置き場

| ファイル | 役割 |
| --- | --- |
| `plan.ts` | 単価と通貨と暦。判定は書かない |
| `queries.ts` | 状態の解決、課金人数、請求明細の読み書き |
| `stripe.ts` | 決済代行への口。`BILLING_MODE` で中身が入れ替わる |
| `monthly.ts` | 巡回。前月ぶんの請求と、おためし終了の知らせ |
| `scripts/run-billing.ts` | その巡回を手で一度回す（`pnpm billing:run`） |
| `mail.ts` | 文面。宛先は組織管理者だけ |
| `actions.ts` | Server Action。凍結中でも通る唯一の操作 |
| `FrozenBanner.tsx` | 凍結中に全画面の上へ出す帯 |

## 決まり

- 状態を列に持たない。おためし期限、免除、支払い方法、未払いの有無から引くたびに計算する。
  日次で更新する形にすると、日付が変わっても切り替わらない時間帯ができる。
- 凍結の判定は二段。`currentScope()` が `OrgScope.frozen` を載せ、
  書き込みの SQL は `orgNotFrozen()` でもう一度確かめる。画面の値を信用しない。
- 書き込みの条件を新しく書くときは、`orgNotFrozen('$1')` を足すこと。
  スレッド、コメント、タグの付与、添付は `threadWritable()` が共有しているので不要。
- 課金人数は `count(DISTINCT user_id)`。抜けてから戻った人は所属の行を二つ持つ。
- 数えた結果は `billing_invoices` へ焼く。請求のたびに数え直さない。
  数え直すと、確定した請求の正しさが「過去の行が二度と動かないこと」に依存する。
- 請求を切る暦は日本標準時に固定する（`BILLING_TIMEZONE`）。
  ただし「その月に在籍したか」の境目だけは組織の `timezone` で見る。
- 金額はセントの整数で持つ。`UNIT_PRICE = 100` は $1.00 である。
  円のような小数を持たない通貨とは、同じ 100 でも意味が違う。
- 税を別に取らない。適格請求書発行事業者の登録をしていないので、
  納めていない税を税として請求する形にしない。単価そのものが税込である。
- 巡回は日で区切らない。対象月はいつ走らせても前月で、二巡目以降は 0 件になる。
  1日だけに走らせる形にすると、その日に落ちていた月の請求が飛ぶ。
- 新しい class を作らない。帯は `.app-note.warn`、請求の記録は `.app-people` を使う。

## BILLING_MODE

| 値 | ふるまい |
| --- | --- |
| `off` | 判定しない。全組織が書き込める。巡回も走らず、画面は 404 |
| `fake` | Stripe を呼ばない。押すとその場で登録済みになる。ブラウザ試験用 |
| `stripe` | 本物。`STRIPE_SECRET_KEY` と `STRIPE_WEBHOOK_SECRET` が要る |
